# 词语审核参考标注

这三张表由 AI 助手标注，不是用户标注或人工金标。来源及限制记录在
[`labels.provenance.json`](./labels.provenance.json)。本轮不调用真实模型，也不修改生产数据。

- `y`：按当前候选内容，建议入题。
- `n`：当前内容不宜入题，原因写在 `note`；不是永久封禁词面。
- `?`：事实、熟悉度或玩法边界不能可靠确定，不用于二元误放/误拒统计，也不自动发布。
- 瞎掰王同时考虑核心释义与使用提示；词本身有趣不抵消释义错误。

## 判断口径

- **你画我猜**：普通中文玩家熟悉；能用不含文字的普通简笔画表达；结合现有字数及拼音提示，
  不会主要依赖猜同义句。角色与地标不因专名直接淘汰，分类错误不代替词质判断。
  零声母字不影响可玩性。需要试玩才能确定的精确匹配边界标 `?`。
- **谁是卧底**：双方熟悉度接近；存在具体自然共性与独立区别；不是同义词或明显上下位关系；
  互换阵营仍可描述。每条接受备注同时给出共同描述方向和区别。
  对宽窄义和日常称谓重叠保留不确定，不因审核方少写一条区别就断言词对不可玩。
- **瞎掰王**：沿用真实准确、真义陌生、字面不泄底四项门槛，加假释义空间或揭晓价值至少一项。
  只猜到材料或大类不等于猜中具体用途；反过来，也不能靠时代、元素成分或工艺参数让普通词假装冷门。
  专业来源本身不是拒绝理由，揭晓应能让普通玩家理解。

## 数据与评测限制

初始抽样按生产接受/拒绝等层分组，不是按实际库存占比随机抽样；百分比只描述这份样本，
不能当作全库误放率或真实玩家满意度。之前的排查已看过部分词的生产结论及真实复审结果，
因此不能宣称完全盲标。本轮不依据这些结果反推标签。

瞎掰王部分事实判断核对了已保存的来源片段，并未逐条做最新网页检索。仅有来源不保证内容正确，
无法确定的机制或历史断言保留为 `?`。`f014`「关扑买卖」与提示词校准样本「关扑」近义，
不是独立留出，标 `?` 排除；抽样也未保证另外两个游戏与原提示词零交集。因此这些表只作为开发参考，
不能包装成全新的独立验收集。

评测脚本会读取来源元数据、明确显示 AI 参考性质；真实运行报告也随 `options.labelProvenance`
保留来源。以前生成的报告早于本次标注，不回写、不伪造其运行时的标注信息。
应先冻结标签，再比较后续版本；不得为提高分数追改标签，评测词及近义改写不得加入提示词。

## 使用

从仓库根目录运行，不加 `--run` 不发送模型请求：

```bash
node scripts/word-review-eval.mjs drawguess
node scripts/word-review-eval.mjs undercover
node scripts/word-review-eval.mjs fibking
```

无需用户逐条重标。只有需要决定玩法取舍或事实补证时，才单独处理 `?` 项。

真实调用仍须另行确认并在本机环境配置 `GEMINI_API_KEY`，不要把密钥贴进聊天或写入数据文件。
`--run` 时 `--delay` 至少 5 秒，重复轮次之间同样等待；这只约束本次评测，仍须考虑同项目的其他请求。
你画我猜和谁是卧底单次最多 5 条，瞎掰王最多 1 条；更小的 `--batch` 可用于对照。
每张表的 id、标注和理由必须完整对应样本；缺失、重复、未知 id 会直接报错。

新报告保存模型、生成版本、审核版本、实际批量与标注来源，并逐轮输出相对参考标注的统计。
HTTP、输出校验或审核缺失不会被当成拒绝：报告仍保存，但进程以非零状态结束。
模拟请求只验证工具行为，不计入模型质量结果；没有真实新旧对照前，不宣称准确率提高。
