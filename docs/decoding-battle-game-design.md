# 解码战：设计草案

状态：正式玩法、本地定向验收及真实八轮 E2E 已完成；推送后仍需远端单 spec 验证，尚未部署生产。游戏 ID 使用 `decrypto`。

## 已确认

- 以桌游《截码战 / Decrypto》为玩法参考。
- 解码战属于小游戏。
- 4–8 个玩家席位，默认 6 个；固定两队，人数尽量平均。
- 分队先由系统随机均分，房主可自由将玩家换队；每队至少 2 人。满足最低人数后，
  人数不平衡仍允许开始，但要提示。
- 房主点击「开始游戏」后进入游戏内分队阶段，确认分队后进入后续游戏流程。
- 分队使用房间内弹窗：两队名单和人数并排显示，房主可调整玩家换队；
  提供「重新随机」和「确认分队」。全员看到分队弹窗与实时结果，只有房主能调整和确认。
- 开始游戏后显示强制分队弹窗，不能取消或返回大厅；系统先随机均分，房主调整并确认。
  至少每队 2 人；满足最低人数但队伍不均时提示后仍可继续。分队状态属于对局，断线或重连不改变已分配的队伍。
- 是否在线不影响分队或其他玩家继续操作；只有当前行动确实依赖掉线玩家时才需要等待其操作。
- 出题人有两种模式：随机选择每队首位出题人，之后按该队座位顺序轮换；或由各队自行
  选择一位出题人，整局由该人出题。房主在创建房间的游戏配置页选择模式；固定出题模式在
  开始游戏后的分队弹窗内为每队设一个专门的出题人位置，大家商量后由房主操作选人；
  两队均选好出题人才能确认分队。已选出题人换队时清空其原队的出题人位置，由房主重选。
  重新随机分队时清空两队出题人，由房主重新指定。
- 随机轮换模式在房主确认分队后，才随机选择两队的首位出题人，并在游戏界面公布。
- 创建房间前的配置页出题模式默认「随机轮换」；房间内配置编辑沿用平台现有共享配置入口，
  大厅摘要只展示当前模式，不新增单独的设置按钮。
- 对局界面顶部直接显示两队本轮出题人，轮换时更新。
- 固定模式的出题人掉线时不更换，等待其重连。
- 确认分队后，进入独立的游戏界面，而不是继续以座位盘作为对局主界面。
- 对局界面分为两个 Tab，对应原版记录纸的正反两面，各记录一队的线索和密码；
  此前「同一页上下同时显示」已被用户纠正。
- 己方四个关键词位于记录板上方，切换两队 Tab 时仍可见，但随页面滚动而移走；
  对方关键词不显示。
- 己方四个关键词按编号一排显示，长词换行而不缩小字体。
- 每队记录保留纸面按轮次记录和按 1–4 号归档两部分，但使用适合手机的卡片布局，
  不照搬原版纸张外观。
- 顶部用文字和数字显示两队进度，如「拦截 1/2 · 误解 0/2」，不只依靠颜色或图标。
- 每个队伍 Tab 的当前轮操作下有一个历史区域，使用「历史线索」「往轮记录」Tab 切换，
  默认展示历史线索。往轮记录用轮次切换器一次显示一轮，默认最新已揭晓轮次；
  按线索逐行并排展示本队猜测和正确编号，第一轮没有拦截的一方显示无拦截。
- 按编号归档的历史线索使用两列两行的四张卡片。
- 历史线索默认全部展开，通过页面滚动查看。
- 历史线索显示所属轮次，便于回查往轮详情。
- 解码或拦截时，每条线索分别选择数字，提交前可单独修改。
- 点击线索右侧的数字框，再从 1–4 中选择；不在每行常驻显示四个按钮。
- 若选择已用于另一条线索的数字，则交换两条线索当前的选择，避免数字重复。
- 对方记录只展示公开线索，不添加猜测对方关键词的笔记。
- 队伍讨论后，由符合当前阶段操作条件的队员提交解码或拦截答案，无须提前指定代表；
  同队第一个成功提交的答案生效，其他未提交草稿不算数。
- 队伍答案提交后立即锁定，不能修改。
- 队伍答案锁定后，本队其他队友可见具体数字；对方公开前只能看到提交状态。
- 出题者在同一张当前轮卡片中同时填写三行线索，每行显示密码数字和对应关键词；
  提交后线索立即锁定；两队出题者都提交后，按当前处理的队伍逐队公开线索。
- 已公开某队线索后，双方可同时填写该队密码的解码和拦截；双方提交后自动推进。
  第一轮只需解码，不拦截，解码提交后自动推进。
- 结果在同一张卡片中自动依次揭晓：先拦截答案、再解码答案、最后正确密码；
  第一轮跳过拦截。答案提交齐后自动开始，不需要房主逐步点击。
- 揭晓完毕后停留在结果卡，由房主点击继续，切换到另一队线索或下一轮。
- 进入新阶段时自动切到当前行动队伍的 Tab；玩家仍可手动切换，未提交的输入不丢失。
- 不设置阶段倒计时。
- 需要猜词决胜时，双方提交猜测并公开答案后，由房主逐项判定是否正确。
- 奖励采用小游戏的 15 经验、3 次普通抽奖，每日目标 1 局；正常完成且至少有 4 名真人时
  对符合资格的玩家结算，中止不结算。
- 个人统计记录完成局数、胜场及胜率；胜率为胜场除以完成局数，不单独统计平局。
- 决胜猜词后仍相同按原版双方共同获胜；双方各记一场胜利。
- 线索规则写入玩法说明，玩家在线下自行判断违规；系统检查三条线索非空，不自动处罚。
- 使用应用内置词库，不允许房主自定义补充；后台生成的词先进入共享投稿审核队列，
  只有人工审核并发布后才会进入对局库存。
- 解码战拥有独立词库，复用平台供词、审核和发布机制，后台可持续补词；每局从已发布词库
  为双方各抽取四个不同关键词。
- 机器人用于测试，由房主代入操作；不是自主 AI。遵循平台已有机器人占座与接管机制，不另设是否支持机器人的玩法选项。

## 参考规则

参考 [Decrypto 规则书](https://cdn.meepletron.com/rulebooks/decrypto/decrypto-rulebook.pdf)
和 [Board Game Arena 规则说明](https://zh-cn.doc.boardgamearena.com/Gamehelpdecrypto)。
每队有四个固定关键词，轮流派出出题者，用三条线索传递一组三位数字密码。
队友尝试解码，对手从第二轮起尝试拦截；密码数字和顺序均须全部正确。
己方解码错误记一次误解，对方拦截正确记一次拦截。完成整轮后判断胜负：
两次拦截获胜，两次误解落败；冲突或第八轮仍未决胜时，比较拦截数减误解数，
仍相同则猜对方关键词，再相同则平局。线索有约束，需要单独设计中文规则与违规处理。

用户已选择不限时，因此不采用原规则书的沙漏时限。

## 已批准的体验与流程

线下同桌，每人使用自己的手机，讨论通过线下口头进行，不做应用内聊天。
每队开局随机取得四个彼此不同的关键词，本局保持不变，分别编号 1–4；
队伍成员知道己方词，对手与旁观者不应在界面上看到。
每轮每队一位出题者，按所选模式轮换或固定；系统私下给其一组三个不重复的数字。

每轮流程：

1. 两队出题者各自提交三条有序线索；两队都提交后，按当前处理的队伍逐队公开。
2. 先处理第一队的密码：己方非出题者讨论并提交解码；从第二轮起，
   对手可同时讨论并提交拦截。双方提交后自动进入分步揭晓。
3. 交换队伍，重复解码与拦截；第一轮两队均不拦截。
4. 记录线索、数字归属和本轮标记，供后续回合查阅。整轮完成后判断胜负；
   未结束则按所选模式轮换或保留出题者，并抽取下一组密码。
5. 需要猜词决胜时，双方各提交对方四个编号对应的关键词；答案公开后由房主逐项判定，
   再比较正确数量。

双方完成必要提交后自动依次揭晓；不设置超时、自动代填或自动判错。
揭晓完毕由房主继续，不由房主逐项推进每个揭晓动画。

## 界面和隐私

- 大厅复用共享房间、座位、配置、分享和主持管理；配置页设置出题模式，开局后用不可取消的强制分队弹窗。
- 游戏中展示己方四个关键词、当轮线索、公开进度与历轮记录；引擎投影裁剪对方关键词、密码和未公开猜测。
- 房主接管机器人时，Worker 在验证房间、房主及机器人席位后，按需返回该席位的私密视图（词卡、出题密码及本队提交）；不广播该额外视角。名单、接管、退出及接管状态完全复用共享舞台能力。
- 终局复盘使用平台统一入口，展示胜负、标记、关键词与每轮记录。
- 独立设计名称、界面和词条；不复制原作素材或词卡。

### 手机对局界面

**纸面参考。** [原版规则书](https://cdn.meepletron.com/rulebooks/decrypto/decrypto-rulebook.pdf)
和[图解规则](https://ezmail.ultraboardgames.com/decrypto/game-rules.php)描述了两种互补的信息：
队伍屏风上是本队固定的 1–4 号秘密关键词；每队有自己的双面记录纸，按顺序写每轮的
三条线索及猜测，揭晓后再把线索归入对应数字的四个区域。两队各自记录两边公开的线索，
不是直接查看对方私人笔记；未公开线索、密码及尚未公布的猜测不属于公开记录。
对手看不到关键词，但能利用以前揭晓的「编号—线索」关系拦截。
实现借鉴其信息组织的原创界面，不复制原版纸张或美术。

**页面结构。** 大厅继续复用座位盘；开始后先显示此前确认的强制分队弹窗，
确认分队再进入独立的游戏工作区。参考一眼成对和你画我猜：继续使用共享
`RoomShell` 的 `stage` 容器、房间标题、名单、菜单、连接状态和机器人接管入口，
主区换成解码战自己的词卡与记录板，游戏中不铺开座位盘，也不叠加大厅手牌。
这是页面内容切换的方案，不预设必须新增路由。

**主界面：** 顶部显示轮次、当前哪队的线索、阶段、两队本轮出题人、双方拦截/误解标记及名单入口；
中间是工作板；底部是当前阶段的操作。词卡不放进「查看词语」弹窗。
工作板分为两个队伍记录 Tab，对应纸的正反两面：每面都有本队历轮线索和揭晓的编号，
以及按 1–4 号归档的历史线索。关键词原本在队伍屏风上，不属于两面记录纸本身；
手机上将己方四个关键词放在记录板上方，切换 Tab 时仍可见，随页面滚动而移走；
不显示对方关键词。
记录区保留纸的两部分信息，用手机卡片布局而非照搬纸张。切换 Tab 不清空当前输入。
下面示例仅用于说明信息布局：

每队记录板按编号聚合该数字的历史线索，同时保留按轮次查看的记录。四张卡片需支持长词
和多条记录；历史线索以两列两行卡片展示，默认全部展开，长内容可换行，
不能靠缩小文字硬塞；没有历史时显示「暂无线索」。提交解码区域中的数字只是玩家
当前猜测，尚未揭晓时不能当作真实归属写入记录板。

**对方记录：** 按对方 1–4 号分别列出所有已揭晓的线索；对方关键词不显示。
例如对方 1 号下是「星光、夜晚」，2 号下是「暖炉」；本轮尚未揭晓的三条线索
单独按顺序显示在操作区，不能提前归入 1–4 号。新阶段自动切换到当前行动队伍的 Tab，
玩家仍可手动切换；第一轮明确显示「本轮不拦截」。
可另按轮次展开双方历史及已揭晓结果；编号记录和轮次记录是同一公开历史的两种视图。
对方记录不提供猜测关键词的笔记。

**分队：** 固定出题人改为每队顶部下拉选择，名单去掉单选框；收起时名字单行省略，
点真人名字可展开全名及座位号。机器人用独立座位号加「机器人」显示，换队使用无圆框的共享图标按钮，保留触控区域。
弹窗注明「每队至少 2 人」；达到下限的换队图标变灰，点击显示就地原因，不发请求。

**出题者：** 需要展示己方词卡；词卡下使用紧凑的共享舞台密码卡：浅底细边框、队伍色左侧强调线，左侧粗体「本轮密码」，右侧横排三个独立大数字格。不加锁图标、列表序号、重复说明或大片留白。
当前轮线索区同时显示三行，每行包含本次密码数字、
对应关键词及一条线索的输入框。密码、关联和未提交的草稿只属于出题者视角。
其他队友在出题期间看到己方词卡与等待状态，不能看到密码或草稿。
两队各有独立的出题视角；线索提交后立即锁定，两队都提交后，按当前处理的队伍逐队公开。

**解码 / 拦截：** 己方解码时同屏看己方词卡和三条当前线索；对方拦截时同屏看对方
编号历史和其三条当前线索。三个答案位置按线索顺序排列，点击每条线索的数字框后从 1–4 中选择，提交前可单独修改；
三个数字不能重复；选择其他线索已用的数字时交换两条的选择。同队符合条件的队员先提交者生效；
答案提交后立即锁定，不能修改。
队伍答案锁定后，本队其他队友可见具体数字；对方公开前只看到提交状态。
未轮到行动的人显示当前阶段和双方提交状态，但不显示无权查看的未揭晓答案。

**揭晓：** 答案提交齐后自动推进，同一张结果卡片依次显示对方拦截、己方解码、正确密码，第一轮跳过拦截；
每项结果轻量入场，三个数字依次翻开，不新增手动推进或客户端计时器；减少动态效果偏好下无动画，但公开顺序不变。
最后三条线索逐行对应正确编号与双方猜测，标明正确/错误。揭晓后才将线索按正确编号加入对应队伍的记录板，
并更新两队拦截、误解标记。不设阶段倒计时。
终局显示胜负和标记，完整关键词与历史进入平台「本局复盘」；猜词决胜由房主判定。

**权限和适配：** 旁观者及未入座房主只展示公开记录；房主接管机器人时按被接管席位的
视角显示。关键词和密码由服务端私有投影裁剪，不能仅靠客户端隐藏；Engine 和 Worker
定向测试覆盖权限边界，E2E 验证各席位实际可见内容，不替代服务端权限测试。
队伍、状态和错误使用文字而非仅靠颜色；字段有标签、支持键盘及屏幕阅读器。
输入时保留草稿，切换或滚动查看记录时不清空；键盘打开后操作仍可到达，本地草稿不冒充服务端已保存。

## 技术实现与范围
