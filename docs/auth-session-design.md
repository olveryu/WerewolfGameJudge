# 身份与账号缓存

## 状态归属

- `CFAuthService` 保存凭据与稳定的 `AuthSession`，登录、恢复、退出和过期通过 `subscribeAuth` 发布。
- `AuthSession.initialUser` 是认证响应的缓存种子，不是实时资料；离线恢复只有身份时为 `null`。
- `AuthContext` 组合身份、初始化反馈与 TanStack Query，不独立保存用户资料。
- 当前资料缓存键为 `['authUser', userId]`，统计为 `['userStats', userId]`，抽奖状态为 `['gachaStatus', userId]`。

## 身份切换

身份发布时取消并移除旧查询，再使用认证响应初始化新用户资料。每次认证建立新的快照，同一个用户重新登录或游客升级也会替换旧缓存。

HTTP 请求绑定发起时的快照。旧请求不得使用新会话的令牌刷新、重试、宣布过期或返回成功。刷新锁按会话隔离；查询取消信号传递给资料、统计和抽奖状态 GET。

登录和退出调用方只等待认证操作，不再调用 `refreshUser` 完成身份切换。既有房间离座与账号切换限制保持不变。

## 资料更新

`refreshUser` 显式刷新并传播失败，保留最后确认的资料。已保存的资料刷新失败由 `refreshSavedProfile` 返回单独结果，界面提示“已保存，资料刷新失败”，不能显示保存失败或完全成功。

初始化错误进入启动错误界面；显式重试重新执行会话恢复。离线身份不伪造完整用户资料。

## 验证边界

回归测试覆盖登录无需额外资料请求、退出清理缓存、迟到响应、同身份升级、初始化失败重试、旧请求 401 与刷新完成，以及保存和刷新结果分离。

本阶段不修改房间会话所有权、抽奖幂等记录或服务端 outbox。没有数据迁移，回滚不涉及资产账本。
