# 猩红蜂舞：首夜实现

## 已确认的产品规则

- 只自动处理首夜、天亮和警长竞选；后续夜晚与白天由线下主持。
- 预设为四名平民、三名普通狼人、猩红狼王、预言家、女巫、守卫和蜂之狂猎。
- 普通狼人与猩红狼王互不相认，狼王不参与首夜普通狼队投票。首夜顺序为守卫、普通狼队、狼王、女巫、预言家；蜂之狂猎没有首夜行动。
- 狼王技能可用时必须选择一名玩家附着，允许选自己。交换影响实际落点；夜间确认不泄露交换，天亮公布实际落点，复盘说明选择与落点。
- 首夜新标记在白天公布后才触发神职陷阱，因此当晚正常查验、守护、解药和毒药不额外触发陷阱。标记不改变身份、阵营或查验结果。
- 狼王在完成标记后死亡时，未被封锁的死亡连带使新标记者死亡；恶灵骑士免疫夜间伤害，因此不会被猩红连带杀死。狼王被救活不触发连带，自标不重复记录死亡。技能封锁同时禁用标记和死亡连带。
- 天亮后全员持续看见实际标记者，包括标记者当晚死亡的情况；警长竞选期间保留。只展示结果，不公开狼王身份、私有死因或封锁详情，不增加播报、确认或竞选等待。
- 完整角色说明包含跨夜技能，但不新增多夜行动、回合计数、标记配额、蜂刺状态或完整胜负裁决。

[网易官方介绍](https://langrensha.163.com/news/official/20261022/26904_1317434.html)
说明了板子配置、两名角色的基本技能与狼王不自爆、互不相认。首夜新标记的生效时点来自用户提供的问答；首夜死亡连带、封锁及其他上述边界是用户明确确认的解释，不声称官网逐项规定。用户后续明确更正：恶灵骑士的夜间伤害免疫也阻止猩红连带。

## 工程建议与未决事项

- 使用角色声明、共享选人和死亡效果机制；标记是权威事实而非身份转换。昨夜信息供房主回查，复盘记录完整行动与死亡原因。
- 用户已确认的规则没有未决问题。实际遇到无法从这些决定推导的跨角色交互时，需提供具体情境并征求决定。
- 玩家流程清单须由正式命令场景生成，逐行差异与完整候选经用户明确批准后才能更新基准。
- 用户后续允许立绘使用占位资源；当前两名角色的头像和徽章使用现有空白牌占位，不是正式美术。

## 实施状态

角色、预设、死亡连带、公共公告、资源登记及交互场景已接入。用户已明确批准首夜玩家流程清单候选及逐行差异，基准已通过审核更新工具更新。
开始和结束语音已使用项目规定的声音参数生成。本机旧版客户端导致 HTTP 403，升级会话内工具后按用户授权使用 `--insecure` 生成。
