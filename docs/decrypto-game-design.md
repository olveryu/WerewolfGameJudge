## 1. 需求定稿表（11 项，缺一不可）

| #   | 项目                                                                     | 定稿                                                                                                                                                                                           |
| --- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 人数与身份/角色构成                                                      | 4–8 人，默认 6 人；两队各至少 2 人，房主可调整并允许不均衡；无独立身份查看流程。                                                                                                               |
| 2   | 阶段流转图                                                               | 大厅 → 开始后强制分队弹窗（不可返回）→ 准备词库 → 两队出题 → 逐队解码/拦截 → 自动分步揭晓 → 房主继续；整轮判断结束或下一轮，必要时猜词决胜。细节见[设计草案](decoding-battle-game-design.md)。 |
| 3   | 每阶段的行动与胜负判定                                                   | 按[设计草案](decoding-battle-game-design.md)中记录的 Decrypto 胜负规则；猜词决胜由房主逐项判定，同数双方共同获胜。                                                                             |
| 4   | 阶段时长与超时处理                                                       | 无玩家行动截止时间；答案提交齐后自动分步揭晓，揭晓完毕由房主继续。断线不自动代交答案，需该玩家行动时等待其重连。                                                                               |
| 5   | 公开/私有信息边界（visibility 裁剪口径）                                 | 本队词语仅本队；密码仅出题人；锁定答案对本队可见，对方仅见提交状态，公开后依次揭晓。房主接管机器人时只取得被接管席位的词语视角；猜词裁判阶段的双队词语仅房主可见。                             |
| 6   | 机器人行为（接管口径，沿用平台接管规则）                                 | 机器人不自主行动，房主使用平台接管机制代操作。                                                                                                                                                 |
| 7   | 配置项（Config 字段与默认值）                                            | 人数默认 6；出题模式默认随机轮换，另一选项为固定出题。                                                                                                                                         |
| 8   | 结算与奖励口径（flat / levelRoll 策略、经验/抽奖公式与资格）             | flat：15 经验、3 次普通抽奖，每日目标 1 局；正常终局、至少 4 名真人时对符合资格者结算，中止不结算。                                                                                            |
| 9   | 失败与边界（掉线、重连、空座位、中途退出）                               | 分队阶段不能返回；配置和分队会随服务端状态重连恢复。在线状态不影响其他玩家继续操作；当前行动依赖掉线玩家时等待重连。房主可按游戏内中止流程结束未完成局且不结算。                               |
| 10  | 文案清单（底部消息/进度行/按钮/说明页的自有声音）                        | 按已确认流程提供阶段状态、提交/等待/错误文案；说明线索限制，违规由玩家线下判断，系统不作违规处罚。                                                                                             |
| 11  | 战绩（指标来源/归属、结算单位、单位/分母、时间精度、历史/迁移/延迟政策） | 每位符合奖励资格的真人统计正常完成局数与胜场；胜率为胜场 ÷ 完成局数，零局显示无数据；共同获胜双方均计胜，不另计平局。历史不回填，终局即时更新。                                                |

## 2. 机器校验的游戏特征

| 特征         | 声明                 | 生成器要求                                                                                             |
| ------------ | -------------------- | ------------------------------------------------------------------------------------------------------ |
| 私有身份     | `identity=无`        | 有身份时自动启用身份查看与机器人身份处理，并生成隐私投影、查看门槛和房间操作测试。                     |
| 夜晚行动     | `night=无`           | 有夜晚时必须有语音；自动接共享步骤、音频回执、私有动作、正式对局清单及覆盖检查，未完成的场景明确失败。 |
| 其他引导播报 | `guidedNarration=无` | 有其他阶段播报时自动启用音频编排。                                                                     |
| 阶段时限     | `stageDeadline=无`   | 有阶段截止时生成超时协议与边界测试。                                                                   |
| 词语供应     | `wordSupply=both`    | 非 `none` 时要求完成供应模式对应的 workflow/部署接线。                                                 |

机器人座位与主持人接管是平台基线，不是可选游戏特征；身份游戏的机器人身份处理不能因漏选 capability 而消失。

## 3. 平台边界（骨架已接通，不许改口径）

- 服务端是游戏规则和阶段推进的唯一权威；`GameState` 是唯一权威状态。
- 复用共享房间、座位、连接、重连、用户资料与分享基础设施；游戏规则
  进 `packages/game-engine`，Worker 负责认证、持久化与广播，客户端
  负责输入与展示。
- 生成器接入、玩法实现及剩余验收状态见仓库根目录的接入报告；用户已批准提前打开本地小游戏入口，不代表生产发布验收完成。
- 本局复盘：入口（终局底部按钮、房主面板与终局任务）、弹窗与图片分享归平台
  （`packages/web/src/features/room/review/`）；游戏只在 `packages/web/src/games/decrypto/review/` 声明复盘
  文档，用封闭的块词汇表达，不写复盘 JSX。骨架复盘是一页 hero「本局结束」+
  参与者名单；终局事实（胜负、身份、得分、过程）按第 1 节定稿后填入。

## 6. 已批准的战绩与结算口径

- 奖励采用 flat：每位符合资格的玩家获得 15 经验和 3 次普通抽奖，每日目标 1 局。
- 仅正常完成的对局结算；中止不结算。门槛为至少 4 名真人；机器人不计入，匿名真人仍计入门槛。
- 每位符合资格的真人累计完成局数与胜场；胜率为胜场除以完成局数，零局显示无数据。
  决胜后双方共同获胜时双方各计一胜，不另计平局。
- 统计只记录终局事实，不补写历史；正常终局即时可见。游戏状态不设版本字段或读时迁移，
  不完整的新版完成事实必须拒绝，旧版奖励 payload 仅处理原奖励。
- 实现已接入 engine/Worker 的统计 DTO、D1 累计表和共享资料统计展示；针对性测试和迁移成本审查仍待验收。

## 7. 已确认的界面与接管修正

- 正式界面还原已批准原型：双队比分及出题人、横排四词卡、队伍 Tab 内整合本轮操作与历史、逐条线索点选编号、数字轮次按钮仅展示单轮记录。
- 固定出题在每队顶部用下拉框选择出题人，名单不放单选框；此决定替代原型中的行内单选。
- 名字默认单行省略，可点击真人名字展开座位号及全名；机器人名单只显示「机器人」，不重复座位编号。换队复用共享图标按钮，去掉圆框但保留触控区域。
- 分队弹窗明确标注每队至少 2 人；本队达到下限时换队图标变灰，点击就地说明不能再移出，不发送命令。
- 出题人密码使用紧凑的共享舞台卡：浅底细边框、队伍色左侧强调线，左侧为主标题大小的粗体「本轮密码」，右侧横排三个独立数字格。不加锁图标、列表序号或重复私密说明；此决定替代先前的无框数字行。
- 揭晓沿用服务端节奏逐项入场，三位数字依次翻开；首轮跳过拦截。不提前展示结果，减少动态效果偏好下保留相同信息和顺序、取消动画。
- 完全复用共享舞台 HUD 的名单、机器人接管和退出入口，以及 `useBotTakeover` 状态；不另造舞台壳或接管系统。
- 私密读取只补充授权机器人席位的词卡、出题密码和本队提交；席位、局序号、权威修订必须匹配，读取失败提供明确错误及重试。
