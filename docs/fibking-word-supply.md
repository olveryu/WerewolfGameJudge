# FibKing 新题与免费供题

## 发题契约

- `fib_word_sequence` 按词面保存永不回退的全局序号。迁移将现存词库、使用记录、账号曝光、回合快照和审核记录中的词放在序列前段，新词追加在后段。有现存曝光记录的账号将进度初始化到旧题段末尾；新账号从头开始。
- 发题只选当前审核合格（独立模型审核或管理员明确人工通过）、处于启用状态的词。历史中只剩词面或已停用的词保留位置但不发题；重新审核通过时使用原位置。旧词不因来源或曾被拒绝而永久排除，复审更新释义和状态，不重复编号，也不计入每月新增数量。
- 发题走三款词语游戏共用的抽词机制（`platform/wordSupply/wordDraw.ts`）：从本桌没有任何真人见过的题目里均匀随机抽一个，并在同一 D1 事务内保存回合快照、把这道题记入每位参与者的已见记录。题目的抽词编号就是 `fib_word_sequence.id`。
- `word_seen` 每账号每词库一行，记录见过的编号。低进度玩家不再因为和高进度玩家同桌而跳过没见过的题。迁移 `0067` 把原来的每账号最高进度换成「编号不超过该进度的题目都见过」，没有人会重新拿到可能玩过的题。旧表 `fib_word_progress` 和 `fib_word_exposures` 不再读写，但本次迁移没有删除：迁移先于 Worker 部署，旧版 Worker 在部署完成前仍要读 `fib_word_progress`；确认线上不再有读它的代码后，由后续迁移删除。
- 参与者名单在开始准备时写入持久化任务。取消、断线和重试不撤销已见记录；同一任务重试回放原题。
- 本桌没有任何人都没见过的题目时进入 `inventoryExhausted`，不会撤销已见记录或调用本地兜底；新账号仍能玩审核合格的旧题。
- 有瞎掰王已见记录的匿名账号不会因 14 天不活跃被自动删除。微信账号绑定到已有邮箱账号时，两个账号的已见记录合并。
- 清空浏览器数据、换设备但没有登录原账号，会形成不同身份；不能承诺跨不同账号去重。此前已经丢失且所有记录中都不存在的历史无法还原。

## 外部投稿的人工决定

管理员可对外部投稿的待审、审核执行失败或模型未通过候选，单条或批量「人工通过」，不依赖模型或独立资料检索成功，也不强制理由。人工通过只改变投稿资格，不立即进入游戏；之后仍需单独确认发布。发布使用已通过投稿格式及领域校验的原始词义，沿用全局序号、抽词索引与已见记录，不调用外部服务。

原模型结论、证据和失败诊断保留；人工决定由投稿记录及操作事件承载，不生成虚假的模型六项合规记录，也不把 Agent 链接当作独立证据。此路径不改变下文自动供题的审核规则、调度及预算。完整协议见 [Agent 词语投稿](./agent-word-submissions.md)。

## 自动供题

Admin「词库供给」页展示审核拒因分布：近 30 天、当前审核版本下，被拒绝的评审在六项质量检查中各有多少项不通过（真实词项 / 释义准确 / 真义陌生 / 字面不泄底 / 假释义空间 / 揭晓价值），用于定位审核规则的收紧方向。谁是卧底无此分布。

每日 UTC 04:00 Cron 只派发 Workflows，同一天用幂等实例 ID。日常调度每天最多 4 批，每月最多 78 批、100 个新发布词。月度目标不是产量保证，审核可全部拒绝。

经明确授权的一次性补库，可以在手动触发 Workflow 时传入 `batchLimit`（4–78）。它只扩大本次运行可扫描的批次范围，不改变 Cron 默认值、每月 78 批消费上限或 100 个新增词发布上限。`day` 使用真实 UTC 日期；同日已消费的批次和请求不会重跑或退款，后续实例仅领取未消费批次。不得在补库运行期间用另一版本的 Worker 覆盖部署；应先协调发布，再核对真实请求及入库结果。

供题与发题分离。Workflow 先从 `fib_word_candidates` 领取待审候选；队列为空才进行一次 Tavily basic 搜索、一次 basic Extract 和一次 Gemini 提取。搜索围绕器物、民俗、行业等取材方向，不要求检索到现成游戏题卡。最多提取两个网页的相关正文片段，每份资料上限 12,000 字符；提取失败不退回使用搜索摘要。

仅在确需搜索时原子选择主题和具体查询，结果持久化供重放：优先三天内未尝试、启用词少、上次尝试更早的主题；全部处于冷却期时仍可选择。主题内优先最久未搜索的具体查询。原有 78 个查询及下标保持不变，新查询只追加，月限独立固定为 78 批。仅复审的批次不分配主题。历史批次的下标可能只是预留查询，并非实际执行记录；后台明确标注。取材不能保证每个主题有产出。

原有文学、网络、复合词、冷门概念四类仍保留，另按词义维护 41 个主题：民俗礼仪、节令节庆、服饰衣冠、饮食菜肴、茶酒饮品、器物用具、建筑营造、手工技艺、纺织染绣、农耕渔猎、矿冶盐业、商业金融、货币钱财、交通行旅、教育科举、游戏博戏、体育武术、音乐乐器、戏曲曲艺、书画艺术、语言文字、方言俗语、网络文化、职业行话、法律制度、医药养生、植物花草、动物生物、地理矿物、天文气象、科学技术、婚恋风俗、情感词语、酒令酒俗、聚会游戏、江湖行话、戏台道具、戏剧机关、侦探推理、社交礼节、市井俚语；另有不参与均衡的“其他”和未标主题。

新候选在原有生成请求中按释义标注主题，随候选和审核发布，不增加一次调用。历史启用词在工作流开头独立标注，每天最多一次、每次最多 25 个，消耗共享模型额度但不占月批次；强制运行可单独标注一次。分类失败记录错误并继续供词；不匹配的结果保留未标、下次再试，无法归类标为“其他”。标注不改变词的启用状态、序号或已见记录。分类是模型判断而非人工验收，不能承诺各主题立即等量。

Gemini 只能从提供的资料中提取 0–12 个互不重复的词，不得凭记忆凑满数量。类别按每词标注，取材方向不限制整批类别。适配层用 `Intl.Segmenter` 将真实正文分成 8–300 字符的完整句段，为其分配短编号；超长句段不截断，不作为可引用项。生成和审核在 JSON Schema 的短编号枚举中选择引用，程序按当前候选及资料下标还原连续原文；不接受模型直接重写的引文、未知编号或跨来源引用。没有可引用片段时不生成，审核可用空引用明确拒绝。持久化数据和领域校验仍使用原始引用文本，不保存编号，不提供旧输出协议兼容。词面必须出现在同一份资料中，但引用不必重复词头。释义基于事实重新撰写，不复制商业题卡。程序核对引用是否存在；引用是否属于该词及义项、是否支持核心释义、玩家是否熟悉该词仍由独立审核判断，同页出现词面及字符串匹配都不代表事实或词质正确。

每次最多审核六个已有证据的候选，未处理的候选保留到后续批次；后续批次不重复搜索或生成。启用库存中尚无当前审核版本通过记录的词优先入队，不限制类别。通过记录必须与当前释义一致，且审核时间不早于启用时间。若待审队列包含缺少证据的旧库存，本批最多领取三个候选，每个缺证词单独搜索并提取正文，保证补证也不超过原有预算。补证成功后即保存；后续审核失败不会丢失同一释义的已核实资料。

候选只在审核、发布事务提交后离开队列。拒绝旧库存只停用，不删除历史或改变序号；已通过但被月度新增上限挡住的候选回到待审队列，下月仍按当前规则复审。失败批次释放候选领取，但不退还批次或外部请求额度。相同词面、释义、审核版本及证据已审核过时不重复入队；更正释义、证据或审核版本后可以再次考虑，不构成永久词语黑名单。

搜索为空、正文提取全部失败或提取不到候选时，批次正常结束并记录 `noCandidates`，不发起无意义的审核。全部拒绝记录 `allRejected`，其余已审核批次记录 `reviewed`。外部服务错误仍记失败阶段和分类，并终止本次 Workflow，不用空结果掩盖调用错误。

三款词语游戏仅在模型生成入口逐条接收候选；发给模型的完整 JSON Schema 与本地解码分离。HTTP、截断、JSON 损坏、顶层结构错误及超过整批数量上限仍整批失败，不截取前几条。你画我猜按完整词条、卧底按完整词对、瞎掰王按词义及全部来源引用隔离：某条不满足原有格式、分类或引用规则时明确拒绝该条，其余候选继续独立审核，不删字符修词、不降低规则。瞎掰王某一引用失败就拒绝整个候选，不丢掉坏引用后继续接收；资料下标始终对应原始输入。去重在完整校验通过后进行，保留第一个合格身份；卧底包含倒序词对，瞎掰王沿用去空白后的词面身份，不再因批内重复使整批失败。

生成结果的 `validation` 随 Workflow 的 `generate-*` 步骤结果持久化：`receivedCount = validCount + rejectedCount + duplicateCount`。其中 `validCount` 仅表示可进入审核，不代表审核通过或新增库存。部分拒绝/重复只记一条汇总 warning，不作为整次 AI 失败上报；`rejectionSamples` 最多八条，包含原始候选下标、受控 schema 字段路径及固定 issue/rule code，超出样本数记 `omittedIssueCount`。不记录原始词条、释义、引用编号、未知字段名或 Zod message/input。非空批次全部不合格抛 `allCandidatesRejected`，以 `invalidOutput` 失败并保留同样的安全汇总，不入队、不审核；它不同于合法空列表 `[]` 的正常零产出，也不同于独立审核全拒的 `allRejected`。

候选存储、持久化读取和审核/发布仍严格校验；审核缺项、重复、身份错配及非法引用仍整批失败，不补默认拒绝、不下架未完成有效审核的旧词。数据库错误和未知程序异常不当成坏候选跳过。原有 `generation_json` 仍只保存 `{ candidates: [...] }`，不塞入汇总字段；瞎掰王兼容旧 `generate-*` 数组检查点并严格解析其中候选，不因返回格式变化重复生成。没有新增 D1 表、查询或逐条拒绝审计写入；原来被坏条目挡住的合法候选会按原流程入队，后续写入随实际产出变化。批量、库存优先、每批调用上限、请求账本和失败不退款规则不变。

复审不额外增加批次或外部调用预算，也受容量、每月批次和新增目标门禁限制；本月目标或预算已满时等待下月。开关关闭时不会自动复审，等待复审的旧词不会自动停用。部署新提示词不等于线上库存已清洗。

每批 Tavily 搜索与提取合计最多七次，Gemini 最多生成、审核各一次；请求账本在发送前原子限制次数，月度总量即按月批次数推导，未提高此前的免费额度上限。basic 搜索每次一 credit，至多两个 URL 的 basic Extract 每次计入最多一 credit 的预算，实际服务端用量可能为零；节省的请求不自动换成更多批次。不确定请求不退款，HTTP 不自动重试，重启不能再次发送同一操作。失败批次终止，后续日期可在剩余额度内继续。

搜索、提取、候选入队与领取、补证、审核、发布分别为持久化步骤。每词的来源快照、引用下标和原文随审核记录保存，题包保留来源 URL。没有付费模型、Google Search grounding、自动提档搜索或付费额度兜底。Admin 词库面板显示本月 Tavily 实际用量（`X/1000`，免费档月度额度）。该数字统计 `fib_word_provider_requests` 中本月 Tavily 操作（`discovery`、`extraction` 及 `verification-*` 补证变体；`generation`、`review` 是 Gemini 模型调用，不计入）的次数；每操作最多消耗一 credit，因此为 credits 消耗上限。必须使用专用免费项目/密钥，其他应用共享同一个项目的消耗不受这里的计数器控制。

模型生成和独立审核的单次请求上限为 120 秒，对应 Workflow 步骤上限为 130 秒；搜索与提取仍为 30 秒请求、40 秒步骤。两个超时边界必须成对设置，避免步骤先于模型请求结束。真实本地复审曾耗时约 64 秒，原 30 秒请求上限会截断有效审核；延长时限不增加请求次数，也不保证供应商可用性或合格词产量。

所有 Gemini 模型调用共用 `platform/ai/` 的错误契约与单次请求诊断：覆盖你画我猜、卧底、瞎掰王的生成与审核、瞎掰王历史主题分类，以及狼人聊天的普通响应/流建立阶段。原生 Gemini 和 OpenAI-compatible 的协议、业务 schema 仍各自保留；Tavily 不是模型，不接入 AI 错误分类。

错误按 `request`、`http`、`responseJson`、`responseEnvelope`、`contentJson`、`outputValidation` 定位阶段，区分缺配置、超时、主动取消、网络、鉴权、限额、服务不可用和无效输出；HTTP 503 不推断为限流。诊断包含模型、游戏、操作、尝试序号与可用的 pack/workflow/request 关联信息；尚未确定的字段（如构造期配置失败的 `operation`）不填造。HTTP 错误只选取供应商 `status`、脱敏后的 `message`、配额与重试白名单，以及响应提供的 `Retry-After`、请求 ID。错误正文最多读取 16 KiB；非 JSON、格式不符、超大或读取失败只记录标记，不能覆盖原始 HTTP 状态。字段限长 500 字符，配额项有数量上限；隐藏当前 API Key、请求字符串、URL 与 Bearer 凭证，不记录原始正文、模型输出或原始异常 cause。整包 Schema 失败只记 Zod issue code，领域校验只记固定 validation code；逐条生成拒绝按上述安全汇总记录，全部拒绝时同样随异常消息持久化。未知程序异常不冒充网络或输出错误。

完整诊断在调用失败的步骤内部通过既有 Workers logger 记录一次（最终失败沿用既有 Sentry 上报），安全 JSON 摘要同时放入异常消息，能跨 Workflow 持久化保留；批次层只记关联上下文，不重复上报完整模型错误。D1 保留原失败阶段/错误码契约，不存长错误或新增表、查询与写入；瞎掰王主动取消仍映射既有 `timedOut` 账本码，缺配置仍为 `unclassified`，精确原因查看诊断的 `failureKind`。Tavily 自己的失败分类以结构化摘要跨步骤传递，不再从自然语言错误前缀猜测。

HTTP 诊断由调用入口明确标记 `protocol`（`native` 或 `openaiCompatible`），不从错误正文猜测接口。除原生 `error.status` 外，同时保留数值或字符串 `error.code`、兼容接口的 `error.type` 和脱敏 `error.message`；可读取普通 `error` 对象或单元素数组中的同一对象，不从多错误数组任意选取一个原因。保留脱敏的响应 Content-Type；未知 JSON 仅记录 `errorBodyShape` 的容器/值类型，不记录未知字段名或值。`errorBody: unrecognized` 是本地格式标记，不是供应商消息；非 JSON、超大和读取失败仍不保存正文，不伪造原因。所有新增诊断同样随安全异常消息持久化，不改变请求内容、成功响应校验、重试或 D1 写入；此前丢弃的响应无法恢复。

已知 AI 失败在单次请求边界统一补齐实际 UTF-8 请求体字节数 `requestBytes` 和本地单调时钟测得的 `durationMs`（包含响应读取及解析，不是供应商内部耗时）。HTTP、网络和适配器解析错误都保留同样的协议与指标，再通过既有 logger 上报一次，并随安全异常消息持久化；保留原有错误阶段、供应商字段和关联信息。不记录请求内容，不把请求大小或耗时直接当成失败原因；未知程序异常仍原样抛出，不伪装成模型失败。补词的单次调用账本、失败不退款和不自动重试保持不变；若后续引入暂态错误退避，必须另行验证调用预算、幂等与不确定结果，不能绕过账本在 HTTP 层偷偷重试。

不改变批量、额度和自动重试：补词不重试模型，聊天仍只对首次 503 重试一次；可重试的首次失败记 warning，最终失败记 error，客户端响应契约不变。聊天成功响应直接透传，流建立成功不等于 SSE 全程成功；现有 `AI_USAGE` 的 `ok` 仍表示开始转发，本次不缓存或解析流来观测中途故障。旧失败无法追溯恢复此前丢弃的供应商响应正文。

## 简单词淘汰标准

生成和独立审核共用校准示例。参照经常阅读中文、接触影视和大众科普的普通聚会玩家，不把“不是日常口语”当成词义陌生。以下条件任一成立即拒绝，不用其他优点抵消：

| 淘汰条件     | 例子或判据                                           | 对应质量字段                                |
| ------------ | ---------------------------------------------------- | ------------------------------------------- |
| 常见固定词义 | 觊觎、打尖；常见书面语、教材或影视用语               | `isMeaningUnfamiliarToMostPlayers=false`    |
| 熟语直接提示 | 琼浆通过琼浆玉液即可联想到美酒                       | `isMeaningDistinctFromLiteralReading=false` |
| 大众科普概念 | 幸存者偏差；专业名称本身不构成难度                   | `isMeaningUnfamiliarToMostPlayers=false`    |
| 字面泄露答案 | 逐字解释或词面意象能推出核心意思，不要求复述标准答案 | `isMeaningDistinctFromLiteralReading=false` |

审核 `reason` 要求记录常见搭配或使用语境、词面可能提示的意思、揭晓前是否仍有释义悬念；拒绝时优先写关键失败证据。检索用于核实，不用搜索结果数量或模型能否答出替代玩家熟悉度。例词是审核标尺，不是程序黑名单。

审核版本 v11（2026-09-30 起）：独立审核共六项质量检查，分为四项硬门槛与两项游戏性信号。接受当且仅当四项硬门槛全部通过（真实词项、释义准确、真义对多数玩家陌生、字面不泄底）且两项游戏性至少通过一项（至少一种可信的错误释义方向、揭晓后有反差或讨论价值）。好读/拼音口述检查已完全移除，不再作为审核依据。历史审核记录为不可变事件，按其产生时的版本规则保留，不重新判定；当前审核版本的接受记录缺失的库存优先进入复审队列。

本地测试验证规则进入真实请求、质量字段决定拒绝，以及库存复审的数据库行为，不证明模型能稳定识别简单词。上线须人工抽查首批实际审核结果；没有确认结果前不能宣称简单题已全部剔除。

## 真实效果验收

代码验收和词质验收分别记录。候选池、引用校验及通过本地测试，都不能证明可玩库存已经增加。

1. 校准样本与留出样本分开。觊觎、琼浆、幸存者偏差是用户明确否定且已经进入提示词的校准例，不能再拿它们充当独立评测集。此前生产批次拒绝的网络热词只是模型判定记录，不自动视为人工金标。
2. 从实际来源取得候选及原文快照，人工按当前版本六个质量字段标注，记录不确定项。必须包含可接受词、常见词、字面泄底、假释义空间不足及释义证据不足等情况；未标注样本不冒充已通过。固定留出集不得加入提示词。
3. 对同一留出集比较提示词或模型版本，人工复核误放与误拒。需要真实模型请求时另行授权，并占用正常项目额度；不在单元测试、完整质量检查或部署过程中自动调用。
4. 同时报告：来源取材成功率、人工确认通过的非重复新词数、错误接受率、错误拒绝率，以及每个已领取模型操作和每个 Tavily 请求对应的新词数。没有审核词、人工标签或新增词时明确报告零或未评估，不用候选数量代替合格产量。请求次数以 `fib_word_provider_requests` 为准，新增数以 `fib_word_sequence` 为准，`requests_reserved` 只是批次数。
5. 发布目标与付费限制分开决策。当前仍为每月 100 个新词；是否改为按实际消耗、剩余可玩题和覆盖天数补充，需要消费数据及单独确认，不能通过提高候选上限隐式改变预算。

当前已有下文记录的十五个人工批准入题样本，但尚未因此完成生产发布，也没有已完成人工逐项标注的留出集或真实效果对比结果。人工样本、生产库存和自动审核验收分别记录，不以程序测试替代。

## 容量保护

平台每 5 分钟及供题前读取 D1 `meta.size_after` 的整库字节数，包括索引。阈值使用十进制 MB：

| 水位   | 自动行为                                             |
| ------ | ---------------------------------------------------- |
| 300 MB | 告警状态，保留定期清理                               |
| 375 MB | 停止新供题批次；低于 350 MB 恢复                     |
| 425 MB | 拒绝创建新账号和首次创建房间；低于 400 MB 退出此状态 |

已有账号登录、已有房间恢复、删除及正在进行的回合不因容量门禁中断。每次清理最多 100 条过期待审候选、100 条过期审核、100 条无活跃房间依赖的旧使用记录及 100 条已迁移到序列的旧曝光记录。待审候选、审核及使用记录保留 90 天；正在领取中的候选不会被清理。审核快照过期后，仍启用的库存可能再次进入复审。账号进度、词面序号和题包来源不删除。

删除行不保证数据库物理大小立即缩小。程序以之后的实际测量结果决定是否恢复，不假装已经释放空间。整库或免费账户无法容纳无限数据；到达保护水位且安全清理不能降低占用时会保持暂停，不自动付费或删除长期进度。状态存于 `database_capacity`，状态变化及批次失败写入 Worker Logs；Workflow 控制台显示执行终态。
