# FibKing 新题与免费供题

## 发题契约

- `fib_word_sequence` 按词面保存永不回退的全局序号。迁移将现存词库、使用记录、账号曝光、回合快照和审核记录中的词放在序列前段，新词追加在后段。有现存曝光记录的账号将进度初始化到旧题段末尾；新账号从头开始。
- 发题只选当前审核合格、处于启用状态的词。历史中只剩词面或已停用的词保留位置但不发题；重新审核通过时使用原位置。旧词不因来源或曾被拒绝而永久排除，复审更新释义和状态，不重复编号，也不计入每月新增数量。
- `fib_word_progress` 每账号一行。发题从本桌最高进度之后开始，并在同一 D1 事务内保存回合快照、推进全部参与者。低进度玩家会跳过部分没见过的题。
- 参与者名单在开始准备时写入持久化任务。取消、断线和重试不退还进度；同一任务重试回放原题。
- 进度之后没有可发题目时进入 `inventoryExhausted`，不会回退进度或调用本地兜底；新账号仍能玩审核合格的旧题。
- 有进度的匿名账号不会因 14 天不活跃被自动删除。微信账号绑定到已有邮箱账号时取最大进度。
- 清空浏览器数据、换设备但没有登录原账号，会形成不同身份；不能承诺跨不同账号去重。此前已经丢失且所有记录中都不存在的历史无法还原。

## 自动供题

每日 UTC 04:00 Cron 只派发 Workflows，同一天用幂等实例 ID。日常调度每天最多 4 批，每月最多 60 批、100 个新发布词。月度目标不是产量保证，审核可全部拒绝。

经明确授权的一次性补库，可以在手动触发 Workflow 时传入 `batchLimit`（4–60）。它只扩大本次运行可扫描的批次范围，不改变 Cron 默认值、每月 60 批消费上限或 100 个新增词发布上限。`day` 使用真实 UTC 日期；同日已消费的批次和请求不会重跑或退款，后续实例仅领取未消费批次。不得在补库运行期间用另一版本的 Worker 覆盖部署；应先协调发布，再核对真实请求及入库结果。

供题与发题分离。Workflow 先从 `fib_word_candidates` 领取待审候选；队列为空才进行一次 Tavily basic 搜索、一次 basic Extract 和一次 Gemini 提取。搜索围绕器物、民俗、行业等取材方向，不要求检索到现成游戏题卡。最多提取两个网页的相关正文片段，每份资料上限 12,000 字符；提取失败不退回使用搜索摘要。

取材查询使用月度账本原子分配的 `searchIndex`，按 60 个具体主题推进，不再按日期循环八个泛化主题。跨日、手动补库及已消费批次重放都不会复用该月序号；候选复审批次仍消费序号，但不检索。查询覆盖民俗、生活、器物与手艺，是资料发现计划，不是预置合格词清单，不能保证每个主题有产出。

Gemini 只能从提供的资料中提取 0–12 个互不重复的词，不得凭记忆凑满数量。类别按每词标注，取材方向不限制整批类别。适配层用 `Intl.Segmenter` 将真实正文分成 8–300 字符的完整句段，为其分配短编号；超长句段不截断，不作为可引用项。生成和审核在 JSON Schema 的短编号枚举中选择引用，程序按当前候选及资料下标还原连续原文；不接受模型直接重写的引文、未知编号或跨来源引用。没有可引用片段时不生成，审核可用空引用明确拒绝。持久化数据和领域校验仍使用原始引用文本，不保存编号，不提供旧输出协议兼容。词面必须出现在同一份资料中，但引用不必重复词头。释义基于事实重新撰写，不复制商业题卡。程序核对引用是否存在；引用是否属于该词及义项、是否支持核心释义、玩家是否熟悉该词仍由独立审核判断，同页出现词面及字符串匹配都不代表事实或词质正确。

每次最多审核六个已有证据的候选，未处理的候选保留到后续批次；后续批次不重复搜索或生成。启用库存中尚无当前审核版本通过记录的词优先入队，不限制类别。通过记录必须与当前释义一致，且审核时间不早于启用时间。若待审队列包含缺少证据的旧库存，本批最多领取三个候选，每个缺证词单独搜索并提取正文，保证补证也不超过原有预算。补证成功后即保存；后续审核失败不会丢失同一释义的已核实资料。

候选只在审核、发布事务提交后离开队列。拒绝旧库存只停用，不删除历史或改变序号；已通过但被月度新增上限挡住的候选回到待审队列，下月仍按当前规则复审。失败批次释放候选领取，但不退还批次或外部请求额度。相同词面、释义、审核版本及证据已审核过时不重复入队；更正释义、证据或审核版本后可以再次考虑，不构成永久词语黑名单。

搜索为空、正文提取全部失败或提取不到候选时，批次正常结束并记录 `noCandidates`，不发起无意义的审核。全部拒绝记录 `allRejected`，其余已审核批次记录 `reviewed`。外部服务错误仍记失败阶段和分类，并终止本次 Workflow，不用空结果掩盖调用错误。

复审不额外增加批次或外部调用预算，也受容量、每月批次和新增目标门禁限制；本月目标或预算已满时等待下月。开关关闭时不会自动复审，等待复审的旧词不会自动停用。部署新提示词不等于线上库存已清洗。

每批 Tavily 搜索与提取合计最多七次，Gemini 最多生成、审核各一次；请求账本在发送前原子限制次数。每月合计最多 420 次 Tavily 请求、120 次模型调用，未提高此前的免费额度上限。basic 搜索每次一 credit，至多两个 URL 的 basic Extract 每次计入最多一 credit 的预算，实际服务端用量可能为零；节省的请求不自动换成更多批次。不确定请求不退款，HTTP 不自动重试，重启不能再次发送同一操作。失败批次终止，后续日期可在剩余额度内继续。

搜索、提取、候选入队与领取、补证、审核、发布分别为持久化步骤。每词的来源快照、引用下标和原文随审核记录保存，题包保留来源 URL。没有付费模型、Google Search grounding、自动提档搜索或付费额度兜底。必须使用专用免费项目/密钥，其他应用共享同一个项目的消耗不受这里的计数器控制。

模型生成和独立审核的单次请求上限为 120 秒，对应 Workflow 步骤上限为 130 秒；搜索与提取仍为 30 秒请求、40 秒步骤。两个超时边界必须成对设置，避免步骤先于模型请求结束。真实本地复审曾耗时约 64 秒，原 30 秒请求上限会截断有效审核；延长时限不增加请求次数，也不保证供应商可用性或合格词产量。

## 简单词淘汰标准

生成和独立审核共用校准示例。参照经常阅读中文、接触影视和大众科普的普通聚会玩家，不把“不是日常口语”当成词义陌生。以下条件任一成立即拒绝，不用其他优点抵消：

| 淘汰条件     | 例子或判据                                           | 对应质量字段                                |
| ------------ | ---------------------------------------------------- | ------------------------------------------- |
| 常见固定词义 | 觊觎、打尖；常见书面语、教材或影视用语               | `isMeaningUnfamiliarToMostPlayers=false`    |
| 熟语直接提示 | 琼浆通过琼浆玉液即可联想到美酒                       | `isMeaningDistinctFromLiteralReading=false` |
| 大众科普概念 | 幸存者偏差；专业名称本身不构成难度                   | `isMeaningUnfamiliarToMostPlayers=false`    |
| 字面泄露答案 | 逐字解释或词面意象能推出核心意思，不要求复述标准答案 | `isMeaningDistinctFromLiteralReading=false` |
| 仅认读困难   | 难在生僻字或读音，去掉认读门槛后无释义悬念           | `isEasyToReadAloud=false`                   |

审核 `reason` 要求记录常见搭配或使用语境、词面可能提示的意思、除认读之外的释义悬念；拒绝时优先写关键失败证据。检索用于核实，不用搜索结果数量或模型能否答出替代玩家熟悉度。例词是审核标尺，不是程序黑名单。

本地测试验证规则进入真实请求、质量字段决定拒绝，以及库存复审的数据库行为，不证明模型能稳定识别简单词。上线须人工抽查首批实际审核结果；没有确认结果前不能宣称简单题已全部剔除。

## 真实效果验收

代码验收和词质验收分别记录。候选池、引用校验及通过本地测试，都不能证明可玩库存已经增加。

1. 校准样本与留出样本分开。觊觎、琼浆、幸存者偏差是用户明确否定且已经进入提示词的校准例，不能再拿它们充当独立评测集。此前生产批次拒绝的网络热词只是模型判定记录，不自动视为人工金标。
2. 从实际来源取得候选及原文快照，人工按七个质量字段标注，记录不确定项。必须包含可接受词、常见词、字面泄底、难读及释义证据不足等情况；未标注样本不冒充已通过。固定留出集不得加入提示词。
3. 对同一留出集比较提示词或模型版本，人工复核误放与误拒。需要真实模型请求时另行授权，并占用正常项目额度；不在单元测试、完整质量检查或部署过程中自动调用。
4. 同时报告：来源取材成功率、人工确认通过的非重复新词数、错误接受率、错误拒绝率，以及每个已领取模型操作和每个 Tavily 请求对应的新词数。没有审核词、人工标签或新增词时明确报告零或未评估，不用候选数量代替合格产量。请求次数以 `fib_word_provider_requests` 为准，新增数以 `fib_word_sequence` 为准，`requests_reserved` 只是批次数。
5. 发布目标与付费限制分开决策。当前仍为每月 100 个新词；是否改为按实际消耗、剩余可玩题和覆盖天数补充，需要消费数据及单独确认，不能通过提高候选上限隐式改变预算。

当前已有下文记录的十五个人工批准入题样本，但尚未因此完成生产发布，也没有已完成人工逐项标注的留出集或真实效果对比结果。人工样本、生产库存和自动审核验收分别记录，不以程序测试替代。

## 容量保护

平台每 5 分钟及供题前读取 D1 `meta.size_after` 的整库字节数，包括索引。阈值使用十进制 MB：

| 水位   | 自动行为                                             |
| ------ | ---------------------------------------------------- |
| 300 MB | 告警状态，保留定期清理                               |
| 375 MB | 停止新供题批次；低于 350 MB 恢复                     |
| 425 MB | 拒绝创建新账号和首次创建房间；低于 400 MB 退出此状态 |

已有账号登录、已有房间恢复、删除及正在进行的回合不因容量门禁中断。每次清理最多 100 条过期待审候选、100 条过期审核、100 条无活跃房间依赖的旧使用记录及 100 条已迁移到序列的旧曝光记录。待审候选、审核及使用记录保留 90 天；正在领取中的候选不会被清理。审核快照过期后，仍启用的库存可能再次进入复审。账号进度、词面序号和题包来源不删除。

删除行不保证数据库物理大小立即缩小。程序以之后的实际测量结果决定是否恢复，不假装已经释放空间。整库或免费账户无法容纳无限数据；到达保护水位且安全清理不能降低占用时会保持暂停，不自动付费或删除长期进度。状态存于 `database_capacity`，状态变化及批次失败写入 Worker Logs；Workflow 控制台显示执行终态。

## 上线前置条件

生产配置已设为 `FIB_WORD_SUPPLY_ENABLED=true`，部署生效后每日 UTC 04:00 自动供题；测试配置保持关闭。修改配置不等于已完成线上部署，以下条件仍须在部署前确认。

1. 确认 Cloudflare Workers/Workflows 使用 Free；Tavily 使用免费专用密钥且关闭 PAYG；Gemini 项目未关联付费结算，并核对 AI Studio 的实际项目配额。
2. 确认已经完成进度迁移 [0051_fib_word_progress.sql](../packages/api-worker/migrations/0051_fib_word_progress.sql)，再应用 [0052_fib_word_candidates.sql](../packages/api-worker/migrations/0052_fib_word_candidates.sql)，随后部署 Worker。候选池迁移不改玩家进度、题目序号或客户端协议，不提供双轨供题路径。迁移先于使用新表的代码；本地测试应用迁移不等于生产已迁移。
3. 使用 Wrangler 的交互终端配置 `TAVILY_API_KEY` 与 `GEMINI_API_KEY`，不要将密钥粘贴到聊天、命令参数或仓库。
4. 在确认上述条件后启用 `FIB_WORD_SUPPLY_ENABLED=true` 并部署。首批新题发布前，旧账号可能已到达序列末尾而显示题目用完；新账号可从现有合格旧题开始。没有合格库存时同样明确显示题目用完。
5. 检查首批实际词质、来源、配额和 Workflow 每步 CPU。Free 的 CPU 上限仍然存在；本地测试不能证明线上 10 ms 限制满足。超限应保持暂停并缩小步骤，不能自动升级付费。

## 本地验证

`pnpm run quality` 覆盖类型、静态检查及全部单元/集成测试。Workflow 测试运行真实本地步骤与 D1，只替换外部步骤并禁止未模拟的 HTTP 请求。供题回归覆盖候选跨批次复用、空取材、旧库存正文补证、失败释放与证据保留、每批请求上限、月度发布上限下保留候选及过期待审资料清理。格式测试中的示例词义不是人工词质标签，不会用真实密钥跑生成回归。

E2E setup 在本地迁移后显式加载 `e2e/fixtures/fib-word-pool.sql`。已有开发服务器会被 Playwright 复用，因此须确保所复用的测试数据库已加载迁移和种子。不要对生产库执行测试种子。
