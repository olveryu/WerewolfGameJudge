# 词库统一方案（干净版，无实现细节）

> 这是给人看的版本：只讲最终形态和怎么用，不讲代码、接口、数据库、文件名。

## 一、为什么改

以前有两个问题：

1. **两条路**：补词系统生成的词和 Agent 投稿的词，走的是两套不同的流程——各有各的审核、各有各的发布。
2. **两个审的地方**：页面上有卡片流和批次详情两个地方能审，审的动作分在两处。

改完之后：**所有词都走同一条路，页面上只有一个审的地方。**

## 二、最终形态：你打开统一词库看到什么

- 一个页面，三个游戏切换：瞎掰王 / 谁是卧底 / 你画我猜。
- 顶部统计：库存、待你批准、已批准待审核、已拒绝；Tavily 本月用量。
- 搜索框 + 状态筛选。
- 卡片流：每个词一张卡，显示词、释义、分类、来源（后台生成 / Agent投稿）、投稿方、提交时间、状态。
- 没有批次面板，没有批次详情页。

## 三、补词怎么走

- 点“+ 补词” → 系统生成 1 个词 → 它直接出现在卡片流里，状态是“待批准”，和 Agent 投稿的词一模一样。
- 一次点只生成 1 个。补词不受外部投稿开关和 Agent 每日额度影响，但仍受统一审核队列容量限制；队列满时会明确报错，不会丢弃词条。
- 系统补词身份是内部身份，不作为普通 Agent 授权展示或管理。

## 四、审核怎么走（全程在卡片流里）

1. **找词**：搜词或分类，或按状态筛（待批准 / 已批准待审核 / 审核中 / 待发布 / 已拒绝）。
2. **批准**：勾选待批准的词 → 批量批准（或在单张卡上点批准）。批准只是说“你看过并同意送审”，不调用模型。
3. **启动独立审核**：勾选已批准的词 → 启动独立审核 → 模型逐条审，审完变成“通过”或“未通过”。
4. **确认发布**：勾选通过的词 → 确认发布 → 进游戏词库。
5. **其余动作**：人工通过（不经过模型、直接通过）、拒绝、撤回批准、下架——都在卡片流里做。
6. **点一张卡**：打开词条详情——材料、模型审核结论、操作记录、这条词的全部动作都在里面。

## 五、多选 / 全选

- 每张卡一个勾选框；勾了才出现批量栏，批量栏在卡片流上方。
- “全选本页”只选当页可操作的条目（审核中、已发布的不会被全选进去）。
- 勾选只限当页，翻页不保留；没有跨页一键全选。
- 选了不同批次的词：系统按批次分别确认（一次确认一批）。

## 六、删掉的东西

- 批次面板、批次详情页、候选词那条平行的审 / 发流程。
- 所有额度：模型调用每天 8 次 / 30 天 120 次上限、每日补词上限、强制补词、瞎掰王每月配额。
- 自动供给（已经删了）。

## 七、还能查来源

- 每张卡上都有来源、投稿方、提交时间；词条详情里有操作记录（谁批准、谁审核、谁发布或拒绝）。
- 删掉的只是“按批次看一整批”的入口，单个词的来源照样能查。

## 八、不变的东西

- 审和发还是你手动点；模型审核还是你点了“启动独立审核”才跑；发布还是你点了“确认发布”才进库。
- 已发布的词不受影响；库存里的词不受影响。
