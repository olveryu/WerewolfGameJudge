# 共享抽词（瞎掰王 / 谁是卧底 / 你画我猜）

三款词语游戏的选词共用一套实现：均匀随机，每个账号永不重复，读行数与词库大小无关。
实现在 [wordDraw.ts](../packages/api-worker/src/platform/wordSupply/wordDraw.ts) 和
[wordDrawSets.ts](../packages/api-worker/src/platform/wordSupply/wordDrawSets.ts)，表结构在迁移
[0067_shared_word_draw.sql](../packages/api-worker/migrations/0067_shared_word_draw.sql)。

## 1. 契约

- **抽取逻辑只有一份。** 挑词、已见过滤、已见记录和提交协议都在共享模块里。
- **三个词库互不相通。** 共享模块只认整数编号，从不读词表；每个游戏传入自己的加载函数，从自己的表里取内容。

  | 游戏     | 词库表                  | 编号来源                        | 分区             |
  | -------- | ----------------------- | ------------------------------- | ---------------- |
  | 瞎掰王   | `fib_words`             | `fib_word_sequence.id`          | `all`            |
  | 谁是卧底 | `undercover_word_pairs` | `draw_ordinal` 列（计数器发号） | `all` 加每个分类 |
  | 你画我猜 | `drawguess_words`       | `draw_ordinal` 列（计数器发号） | `all`            |

- **每个账号永不重复。** 本桌任一真人见过的词不再抽出；记录按账号保存，跨房间有效。机器人没有账号，不参与。
- **读行数恒定。** 一次抽词读一行可抽索引、每位参与者一行已见记录，再按编号取出抽中的词。

## 2. 数据

- `word_draw_index (pool, partition_key, members)`：每个词库分区一行，`members` 是当前可抽的编号列表。
- `word_seen (user_id, pool, seen)`：每个账号每个词库一行，`seen` 是见过的编号，只追加。
- `word_draw_ordinals (pool, last_ordinal)`：谁是卧底和你画我猜的发号计数器，只增不减。

编号列表是首尾带逗号的文本（`,3,17,42,`），追加和移除一个编号只用字符串函数，不扫行。`word_seen` 还接受
闭区间（`,1-250,`），瞎掰王旧的每账号最高进度就是这样无损迁移过来的。

**索引由触发器维护。** 词表的插入、状态变更、分类变更和删除都会同步 `word_draw_index`，发布、复审、种子和测试
夹具都不需要调用共享代码。编号一经分配不可修改，也不复用。

**把集合压进一行是有意的取舍。** 它违反第一范式，换来的是 D1 按行计费下的恒定读行数。教科书式的「一次见过
一行」在本桌接近耗尽时每次要读几百行，而常玩的那桌人正好长期处在这个区间。

## 3. 流程

**瞎掰王、谁是卧底**（抽 1 个并记录）：

1. 已有本回合快照就原样返回，重试不会抽第二次。
2. 读可抽索引和参与者的已见记录，在 Worker 里均匀随机挑出没人见过的编号。
3. 用游戏自己的加载函数取内容；已下架或被本房间排除的编号换一个再抽。
4. 一个 D1 batch 写入回合快照，并给每位参与者追加已见。快照写入带一个条件：参与者的已见记录自读取后没有
   变过。条件不成立时什么都不写，整次抽词重来。这保证同一账号同时在两个房间也不会拿到同一个词。

回合快照沿用各游戏原有的表（`fib_round_word_selections`、`undercover_round_word_selections`），它们随房间
级联删除，所以流水不会累积。

**你画我猜**（发 3 个候选，选定后记录）：

1. 发候选词只读不写：优先本桌没人玩过的，不够时用玩过的补足，本局已用的始终避开。
2. 画手选定或超时指派后，引擎发出 `drawguess.word.recordSeen`，Worker 把这一个词记入全桌真人的已见记录。
   没被选中的候选词不记，仍可再次出现。

**耗尽**：共享模块返回耗尽和分区大小，由游戏决定怎么办。瞎掰王进入 `inventoryExhausted`；谁是卧底区分
「暂无可用词语」与「新词已用完」，后者可由房主允许使用旧词；你画我猜用玩过的词补足，只有词库无词可发时才报错。

## 4. 读写行数

六位参与者、本地 D1 的 `meta.rows_read` / `rows_written`，2026-11-11 实测。「之前」是 `origin/main` 的选词代码。

| 一次抽词          | 之前（30 词 / 600 词） | 现在（与词库大小、已见比例无关） |
| ----------------- | ---------------------- | -------------------------------- |
| 瞎掰王            | 读 130 / 1840，写 10   | 读 50，写 10                     |
| 谁是卧底          | 读 64 / 1204，写 3     | 读 36，写 9                      |
| 你画我猜发 3 个词 | 读 60 / 1200，写 0     | 读 19，写 0                      |

现在的读行数是每位参与者 5–7 行加一个常数（瞎掰王 7 行，多出的 2 行是原有的「参与者账号存在」检查），其中
每人 2 行用于「已见记录没变过」的提交条件。你画我猜每选定一个词另有一次写入：每位参与者一行。各游戏的选词测试用同一个计数包装（`test/rowCountingDb.ts`）钉住这些数字
不随词库大小和已见比例变化。

**加载函数只按编号查询。** 查询里再带 `status = 'active'` 条件时，SQLite 在一次查多个编号的情况下会改走状态
索引并读完所有启用词（实测 600 词读 613 行）。状态在代码里过滤。

## 5. 账号生命周期

- 账号删除时已见记录级联删除。
- 微信账号并入邮箱账号时，两个账号各词库的已见记录合并。
- 只有瞎掰王的已见记录会让匿名账号免于 14 天不活跃清理（沿用原规则）；其他词库的记录随匿名账号一起清理。

## 6. 已知范围与后续

- `fib_word_progress` 和 `fib_word_exposures` 已不再读写，但迁移 `0067` 没有删除它们：迁移先于 Worker 部署，
  旧版 Worker 在部署完成前仍要读 `fib_word_progress`。确认线上不再有读它的代码后，由后续迁移删除。
- `fib_words.selection_key` 列和 `idx_fib_words_selection` 索引在本次改动之前就已不参与选词，本次没有处理。
- 可抽索引和已见记录都是一行存整个集合，适用于几万词以内的词库；超过后需要分段。
- `INSERT OR REPLACE` 这类不触发删除触发器的写法会在索引里留下失效编号。抽到失效编号时会自动换一个，不会
  报错，但索引本身不会自愈；现有写入路径都用 `ON CONFLICT DO UPDATE`，不受影响。
