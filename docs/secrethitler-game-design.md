> 状态：已实现；按用户最新要求开放创建游戏目录入口，正式部署仍待名称/主题使用权确认
> 游戏 ID：`secrethitler`\
> 展示名：秘密希特勒\
> 游戏层级：`main`，作为独立大卡片游戏\
> 规则基线：官方标准规则，不含第三方平衡变体\
> 方案日期：2026-11-17

> 交互更新：全员投票后有五秒揭晓倒计时；投票、政策和否决结果展示五秒后由服务端自动推进，无需玩家或机器人确认。本文旧有“立即”描述指规则结果，不表示跳过结果展示。

## 2. 定位、人数与开局配置

秘密希特勒是一款 5–10 人、隐藏阵营、线下讨论型的独立大卡片游戏。玩家通过选举政府并秘密施行政策，判断其他人的阵营；法西斯阵营则试图推进法西斯政策并让希特勒当选总理。

### 2.1 角色配比

| 总人数 | 自由派 | 普通法西斯 | 希特勒 | 法西斯阵营总数 |
| -----: | -----: | ---------: | -----: | -------------: |
|      5 |      3 |          1 |      1 |              2 |
|      6 |      4 |          1 |      1 |              2 |
|      7 |      4 |          2 |      1 |              3 |
|      8 |      5 |          2 |      1 |              3 |
|      9 |      5 |          3 |      1 |              4 |
|     10 |      6 |          3 |      1 |              4 |

每局从 6 张自由派政策和 11 张法西斯政策组成的牌堆开始。角色与政策均由引擎生成；随机性必须使用引擎现有的随机输入，不在生产代码中使用 `Math.random`。

### 2.2 开局身份信息

- 自由派只知道自己的身份。
- 5–6 人局中，希特勒与普通法西斯互相识别。
- 7–10 人局中，普通法西斯识别彼此及希特勒；希特勒不知道普通法西斯是谁。
- 阵营调查只返回“自由派 / 法西斯阵营”，不会区分普通法西斯和希特勒。

### 2.3 首版范围

- 严格采用标准 5–10 人规则，不提供可选角色、牌堆重平衡或自定义行动轨道。
- 首局开始时包含一次“首夜互认”语音流程；后续轮次没有夜晚阶段或夜晚语音。
- 不含 App 内聊天、词库、AI 玩家或联网匹配。
- 全员坐满后，房主分配身份；所有真人查看自己的身份后，房主开始首夜语音。
- 首任总统由引擎从全部已入座座位中随机选出，包括机器人。
- 纯机器人测试房间可以分配身份；这不改变结算所需的 5 名真人门槛。
- 测试机器人的身份副标签仅房主可见；其他玩家和旁观者不显示。

## 3. 核心回合规则

### 3.1 选举

1. 总统候选人按座位顺序轮转；特别选举仅在当前政策轨道授权时临时指定候选人。
2. 总统先在弹窗预选一名符合任期限制的存活玩家，确认后全房可见并锁定预选；再打开最终提名弹窗，可保留或更换人选，确认后才进入投票。未提交的调整仅总统可见，取消即丢弃。预选在重连或房主切换代入座位后保留。
3. 所有存活玩家秘密提交赞成或反对。全部提交后开始五秒倒计时，倒计时结束前可修改自己的选择；到期后同时揭晓。
4. 赞成票必须严格多于反对票，政府才通过；平票或反对票较多均视为否决。
5. 投票结果展示五秒后，通过的政府进入立法阶段，**不会清零选举失败计数**；只有施行政策才清零。若希特勒在法西斯政策已达 3 张或以上时当选总理，结果展示结束后揭晓法西斯获胜，不进入立法阶段。
6. 政府被否决时，选举失败计数加一，总统职位顺时针轮转。
7. 未施行政期间累计 3 次政府落选或获准否决时，立即翻开并施行政策牌堆顶的一张政策。该政策不触发总统权力；清零选举失败计数，并清除总理任期限制。若牌堆不足 3 张，在需要开始立法前将弃牌洗回牌堆。

### 3.2 总理任期限制

- 上一届**当选政府**的总统和总理，下一次不得被提名为总理。
- 当存活玩家不超过 5 人时，仅上一届当选政府的总理不得被提名为总理；上一届总统可以被提名。
- 限制针对当选政府，不针对被否决的候选政府。
- 特别选举指定的总统仍遵循总统资格规则；其任命的总理仍须通过当前任期限制检查。

### 3.3 立法

1. 总统私下查看牌堆顶 3 张政策，弃置 1 张，再将其余 2 张交给总理。
2. 总理私下查看这 2 张，施行其中 1 张，另一张弃置。
3. 施行的政策公开放到对应轨道；弃置的政策及总统手牌不公开。
4. 若施行的法西斯政策触发总统权力，当前总统必须完成该权力后才能开始下一次选举。
5. 当牌堆剩余不足 3 张、需要开始新的立法时，将弃牌洗回牌堆组成新牌堆。
6. 总统和总理的手牌在各自行动时自动显示；选牌及否决动作必须确认。政策、否决及投票结果展示五秒后自动推进；触发混乱时，原因与自动施行政策合并显示。

### 3.4 否决权

- 第 5 张法西斯政策施行后，否决权永久解锁。
- 此后立法时，总理可请求否决当前收到的两张政策。
- 总统同意时，两张政策均弃置，选举失败计数加一；若达到 3，按“连续否决”规则自动施行牌堆顶政策。
- 总统拒绝时，总理必须从两张政策中施行一张。
- 同一届政府被拒绝后不能再次请求否决；同意否决不取消该届当选政府的任期限制，除非触发自动施政。
- 否决不会撤销已施行政策，也不会触发总统权力。

## 4. 胜利条件与总统权力

### 4.1 胜利条件

- **自由派获胜**：施行第 5 张自由派政策，或处决希特勒。
- **法西斯获胜**：施行第 6 张法西斯政策，或希特勒在法西斯政策已达 3 张或以上时当选总理。
- 已被处决的玩家仍属于原阵营；若其阵营最终获胜，该玩家也记为阵营胜利。

### 4.2 法西斯政策轨道

总统权力由开局人数确定，整局不变：

| 法西斯政策张数 | 5–6 人           | 7–8 人           | 9–10 人          |
| -------------: | ---------------- | ---------------- | ---------------- |
|              1 | 无               | 无               | 调查阵营         |
|              2 | 无               | 调查阵营         | 调查阵营         |
|              3 | 政策预览         | 特别选举         | 特别选举         |
|              4 | 处决             | 处决             | 处决             |
|              5 | 处决；解锁否决权 | 处决；解锁否决权 | 处决；解锁否决权 |
|              6 | 法西斯获胜       | 法西斯获胜       | 法西斯获胜       |

权力行为：

- **调查阵营**：总统选择一名尚未被调查过的存活玩家，私下查看其党派归属；总统可以自行决定是否、以及如何向其他人转述。
- **特别选举**：总统选择任意其他存活玩家作为下一位总统候选人，包括通常受总理任期限制的玩家。该次政府处理完成后，总统轮转回到发动特别选举的总统左手边，不额外跳过座位。
- **处决**：总统选择一名存活玩家。若目标是希特勒，立即由自由派获胜；否则目标离场，不公开其阵营。被处决玩家不能继续投票、参选或执行行动。
- **政策预览**：总统私下查看牌堆顶 3 张政策，不改变其顺序或内容。

## 5. 首夜互认与游戏阶段

### 5.1 首夜语音互认

首夜只在角色查看后发生一次。身份查看页不列出队友；互认信息由 App 在首夜按阵营私密显示，替代线下手势。App 是唯一电子主持，房主设备承载 `audioOrchestration` 语音播放，不需要真人主持、朗读或逐步点“继续”。房主开始游戏后，音频播放完成与玩家私密查看共同驱动引擎自动推进，不设阶段倒计时。

对局记录摘要整块在大厅、查看身份、首夜互认及收尾播报期间隐藏；最后一段天亮语音完成后才显示政策轨道及选举失败计数，之后保留至终局。

电子主持使用本地打包的中文 MP3 语音，不在运行时上传或合成音频。语音由项目统一的 Edge TTS 生成脚本制作，沿用狼人杀与阿瓦隆的标准声线。房间不显示供真人朗读的主持词，不提供人工朗读兜底或手动结束播报按钮。播放失败时明确报错，保留当前音频批次并暂停首夜，不得假装播放成功或跳过播报。语音不包含玩家姓名或座位号。

播报和断线恢复使用与狼人杀、阿瓦隆相同的共享编排及续播弹窗；续播手势只恢复声音，不跳过必需播报。房主首夜自动播放设置中的背景音乐，沿用保存的音乐/语音音量，可从共享音乐按钮暂停；天亮语音前停止背景音乐，终局、离开房间或失去房主身份时清理。天亮后不自动播放音乐。

首夜只有一个共享步骤，进度为「坏人互认」1/1。开场的“全员闭眼 + 按人数互认指令”是一批音频；全部获准玩家通过「查看夜间信息」完成私密查看且开场整批播放完成后，引擎进入选举并排入“互认结束闭眼 + 天亮睁眼”收尾批次。查看流程先显示“查看夜间信息？”确认，再以步骤名“坏人互认”为内容标题展示授权信息，玩家点击“知道了”才提交查看。开闭眼和天亮不是额外步骤；收尾期间不显示行动进度、禁止提名，提示玩家闭眼等待电子主持通知睁眼，断线重连仍需完成该批播报。5–6 人语音明确叫法西斯与希特勒睁眼，7–10 人只叫普通法西斯睁眼并明确希特勒保持闭眼；获准玩家在自己的设备上查看信息，不使用手势。已查看者只等待其他玩家，不重复显示查看按钮；旁观者不收到玩家行动指令。

互认步骤中，获准且未查看的玩家在共享座位盘上通过头像颜色高亮看到已知队友，沿用狼人杀的同伴高亮，不新增「法西斯」或「希特勒」文字标签；查看后或步骤结束即消失。接管机器人时按当前受控座位的私密视图显示，切回本人时恢复本人视图；旁观者和未获授权的玩家没有这些高亮。

角色卡当前使用平台已有的通用空白立绘占位；公开角色立绘清单由房间共享图片预加载 hook 一次性低优先级预热，不从玩家秘密分配推导。五条首夜 MP3 由固定 `AudioClip` registry 列出；音频绑定的 `prepareQueue` 调用 `AudioService.preloadClips`，让本地音频在播放前开始缓冲。

- **5–6 人**：全桌闭眼；希特勒与普通法西斯在各自设备上私下查看法西斯阵营座位；关闭信息页后全桌睁眼。
- **7–10 人**：全桌闭眼；普通法西斯在各自设备上私下查看其他普通法西斯及希特勒座位；希特勒保持闭眼，且只看到“你不知道其他法西斯身份”的提示；关闭信息页后全桌睁眼。
- 首夜信息仅显示必要的座位身份，不显示任何手势或要求希特勒主动表态。自由派及其他未获授权的座位不得看到法西斯名单或希特勒位置。
- 获准互认的每个座位仍须通过共享步骤的「知道了」提交查看；查看齐全且该步骤语音播放完毕后才自动继续，两者到达顺序不影响结果。测试机器人由房主接管后查看，不会自动跳过。
- 首夜语音不提供重播。播放失败时检查设备语音支持和音频权限后刷新重试，不改成人工主持。
- 语音只提示当前阵营查看或结束查看，不播报玩家姓名、座位或隐藏身份；App 不验证玩家是否闭眼。

### 5.2 游戏阶段与状态机

```text
lobby
  └─ roles.assign → viewing
       └─ 全员查看 + host game.begin → night
            └─ 语音完成 + 获准座位私密查看（引擎自动推进）→ election
                 ├─ government.nominate → voting
                 │    ├─ 全员投票 → 五秒倒计时 → publicResult（展示五秒后自动推进）
                 │    ├─ 政府否决 → election
                 │    ├─ 第三次连续否决 → publicResult 含 chaos policy → election 或 ended
                 │    └─ 政府通过
                 │         ├─ 希特勒当选总理且法西斯政策 ≥ 3 → ended
                 │         └─ legislativePresident → legislativeChancellor
                 │              ├─ 请求否决 → vetoResponse → publicResult → 施政或 election / chaos
                 │              ├─ 施行政策 → publicResult → ended 或下一行动
                 │              ├─ 总统权力 → executive → election
                 │              └─ 无总统权力 → election
                 └─ 处决希特勒 → ended
```

`GameState` 是唯一权威状态。状态至少需要保存：版本、阶段、冻结的开局座位名单、角色与阵营、身份查看记录、首夜步骤及其人数分支、存活状态、总统轮转位置、临时特别选举位置、上届当选政府、选举失败数、两条政策轨道、牌堆与弃牌、当前政府候选人、当前选票、立法中的私有手牌、已调查座位、待执行总统权力、终局赢家及终局原因。

所有转换由纯引擎命令决定；Worker 负责严格校验、持久化、广播和到期调度。当前持久化状态版本为 6；版本 1 的四个播报段迁移为单步互认及收尾批次，版本 1–2 补齐默认公投模式，旧投票阶段迁移为未武装倒计时，保留已有确认、待播音频和对局数据。未知版本严格拒绝。

## 6. 信息可见性

### 6.1 所有人可见

- 当前阶段、总统与候选总理、任期限制、存活座位。
- 已施行政策、政策轨道进度、选举失败计数。
- 投票揭晓后的每名存活玩家选择及赞成/反对结果。
- 政府通过/否决、公开总统行动及被处决的座位。
- 游戏结束后的赢家和终局原因。
- 首夜阶段名称与播报进度；具体阵营座位信息只进入被授权玩家的视图。

### 6.2 仅授权玩家可见

- 自己的角色与阵营；首夜只有符合人数与阵营规则的玩家能看到对应法西斯座位信息。
- 总统的 3 张政策手牌、总理的 2 张政策手牌。
- 总统查看的调查结果和政策预览。
- 投票揭晓前自己的选择；其他玩家的票在全员提交前不显示。

### 6.3 终局揭示与平台信任边界

- 正常终局后，本局复盘可揭示所有座位的角色、党派、最终阵营结果和公开对局过程；非希特勒被处决时的阵营仍只在终局揭示。
- 引擎的 `visibility` 逻辑和客户端视图模型必须阻止不该看到的字段进入对应玩家 UI；7–10 人时希特勒视图不得含有普通法西斯座位信息。
- 首版沿用平台现有线下社交游戏信任模型，不宣称具备对开发者工具、抓包或篡改客户端的协议级防作弊能力；不得把 UI 隐藏描述为加密保密。

## 7. 房间、配置与界面

### 7.1 配置与大厅

- 配置字段：`numberOfPlayers`（整数 5–10，默认 8）、`voteMode`（`public` / `secret`，默认公投）。
- 配置变更仅在大厅有效；房间满员且座位冻结后，不能更改人数或重新抽取角色。
- 公投在结算后同时公开每位选民的选票；暗投只公开赞成 / 反对票数。提交中两种模式都只把本人选票投影给自己，且只在投票弹窗里显示（与阿瓦隆一致）；对局记录与摘要条在提交中只显示「已投 x/y」和未投票座位号。
- 不提供否决次数、特殊角色、政策牌堆或总统权力变体选项。
- 开局门槛：实际人数与所选人数相同；少于 5 人或未坐满时拒绝分配身份。
- 身份分配后进入独立 `viewing` 阶段；玩家只看自己的角色与阵营，不在页面上获知队友身份。
- 全员查看后，房主启动一次性 `night` 阶段；App 按人数播放互认语音，并只向应获知信息的座位展示法西斯队友与希特勒位置；播报和私密查看完成后自动进入第一轮选举。

### 7.2 客户端主要界面

房主管理按阶段保留完整入口：大厅的配置/补机器人/清空/分享/分配角色；
身份查看阶段的开始游戏、标记机器人已查看（并作为未看齐时的任务补救）；
首夜仅针对当前获准机器人座位的批量确认；大厅、身份查看和终局的音乐设置。
所有未结束的已发牌阶段提供二次确认的「中止本局」，清除对局但保留座位、配置与局序号，
不发奖励或统计结算。房主命令拒绝非房主及受控座位通道；播报期间管理操作继续受共享音频锁约束。
正常终局保留复盘、再来一局和返回大厅；中止不伪造终局。

1. 大卡片首页：游戏简介、规则入口、开始建房。
2. 规则说明：阵营目标、身份知识、选举、立法、总统权力、终局条件。
3. 房间大厅：座位、人数设置、房主配置与身份分配。
4. 身份查看：仅显示本玩家自己的角色/阵营及查看确认，不显示队友身份。
5. 首夜界面：电子主持自动播放对应人数语音并推进，仅显示流程状态而非朗读脚本。玩家保留私密互认和查看入口；无重播、手动推进或跳过播报入口。
6. 对局桌面：两条政策轨道、选举失败标记、当前总统/总理、存活座位和本轮公开记录。
7. 行动弹层：提名、秘密投票、总统弃牌、总理施政/请求否决、总统权力目标选择。
8. 终局复盘：阵营胜者、所有角色、各轮政府、揭晓后的投票、施行政策、总统行动及终局原因。

阶段提示和动作位遵循共享房间壳契约：游戏只提供阶段状态、玩家消息和命令意图，不自建房间头部、连接状态、座位管理、主持面板、分享弹窗或复盘 JSX。

房间布局对齐狼人杀与阿瓦隆：所有阶段保留共享座位盘，`RoomGameSummary` 与
`BoardInfoContent` 在同一张卡内展示公开身份构成和投票方式，发牌后默认折叠配置。
卡头统一为「秘密希特勒（N人）」、玩法和折叠入口，不再分开显示游戏标题与配置框。顶部
`RoomStatusSummary` 与狼人杀警长竞选、阿瓦隆共用展示层，在首夜语音结束进入选举后
紧凑显示阶段、政策数和选举失败数；点击后通过共享
`RoomDialog` 查看政策轨道、政府投票、总统行动及终局阵营结果，不在座位盘上方
堆叠大卡片。个人指令、身份查看和私密调查结果入口归底部动作区，私密信息不进入公开记录。

## 8. 命令、权限与失败文案

所有命令由引擎再次校验权限和阶段；客户端禁用按钮只是提示，不能作为授权边界。下表游戏命令统一带 `secrethitler.` 前缀；共享座位及资料命令沿用平台协议。

| 命令                           | 输入与权限                                               | 成功效果                                               | 失败文案建议                       |
| ------------------------------ | -------------------------------------------------------- | ------------------------------------------------------ | ---------------------------------- |
| `roles.assign`                 | 无输入；仅房主；大厅或终局，满座                         | 随机分配身份和首任总统，初始化牌堆，进入身份查看       | 「请先坐满所选人数，再分配身份。」 |
| `role.viewed`                  | 无输入；本人或受控机器人座位                             | 标记该座位已查看身份                                   | 「当前不能查看身份。」             |
| `game.begin`                   | 无输入；仅房主；所有座位已查看                           | 进入一次性首夜阶段                                     | 「还有玩家未查看身份。」           |
| `step.submit`                  | `gameSequence` 与 `StepSubmission`；获准互认的座位       | 记录该座位已查看首夜信息                               | 当前步骤已变化时提示重新选择       |
| `audio.ack`                    | `audioBatchId`；仅房主                                   | 确认对应批次播报完成                                   | 「只有房主可以确认播报。」         |
| `game.returnToLobby`           | 无输入；仅房主；终局                                     | 清空本局玩法信息并返回大厅                             | 「当前阶段不能返回大厅。」         |
| `government.nominate`          | `chancellorSeatId`；当前总统；选举阶段                   | 提名符合任期规则的其他存活玩家，进入投票               | 「当前不能提名该玩家为总理。」     |
| `government.castVote`          | `ja` 或 `nein`；每名存活玩家；投票阶段                   | 写入或更新本人选票；全员提交后按投票模式统一揭晓并结算 | 「当前不在投票阶段。」             |

| `policy.vetoRespond`           | 布尔 `approve`；当前总统；存在待决否决                   | 同意则弃两张并推进失败计数；拒绝则返回总理选牌         | 「当前没有待回应的否决请求。」     |
| `action.investigate`           | `targetSeatId`；当前总统；调查权力阶段                   | 私下返回目标阵营并记录该座位已调查                     | 「请选择尚未调查的存活玩家。」     |

## 9. 掉线、接管、奖励与战绩

### 9.1 掉线和接管

- 不设置阶段超时，也不因掉线自动投票、弃牌、施政或执行总统权力；等待由线下玩家自行协调。
- 重连恢复当前权威状态及该座位有权查看的信息。
- 对局开始时冻结座位身份和统计归属；开始后不允许换人或补座。
- 若平台允许房主接管断线座位，接管者只能代为操作原座位，角色和统计仍归原座位参与者；接管不改变身份或阵营。
- 房主中途关闭房间属于未完成对局，不发放终局奖励或胜场。

### 9.2 奖励建议

- 策略：`flat`。
- 已批准的注册表数值：`xpEarned = 33`、`normalDrawsEarned = 3`、`dailyCompletionTarget = 1`，与现有主卡片游戏阿瓦隆保持一致。
- 至少 5 名真人开局并正常终局后，所有符合平台奖励资格的注册参与者领取同一份奖励；游客计入人数门槛但不领奖，赢家不额外加成。
- 奖励与统计只在权威终局事件中原子结算；重放不得重复累计。中止、房间关闭和未开局不结算。

### 9.3 战绩建议

- **完成局数**：每名开局冻结名单中的真人参与者，在正常终局计 1 局；被处决不影响资格。
- **阵营胜场**：若该玩家开局阵营与最终获胜阵营相同，计 1 胜；自由派和法西斯胜利分别可展示，胜率由累计胜场 / 完成局数计算。完成局数为 0 时显示「暂无数据」，不做除零或显示虚构的 0%。
- **真人与机器人**：匿名真人可参与游戏并满足最低真人人数，但没有注册账户时不进入账户统计或奖励；机器人不计人数、不参与生产局、不结算奖励和统计。
- **历史与时间**：首版只存累计数，不存逐局历史统计，不回填上线前数据；统计在结算后立即可见，无延迟时间戳或单局历史缓存。
- **技术影响**：生成器的 completed-games 统计骨架不足以自动实现阵营胜场。必须扩展严格 v2 终局事实、引擎 DTO/parser、Worker 计数、D1 自有表和迁移、公共统计 DTO 及共享统计面板；旧版 completion payload 仍只按既有兼容规则处理奖励，不推测胜场。

## 10. 引擎、Worker 与数据边界

- 引擎负责所有状态转移、随机角色分配、胜负判定、权限校验和按查看者生成的视图。
- Worker 提供本游戏模块、严格 Zod 命令/配置校验、状态迁移和原子奖励/统计效果；首版不新增 HTTP 路由、工作流、词库或 R2 资源。
- Web 游戏实现静态客户端工厂，客户端只提交玩家意图，不本地判定政策、胜负、身份知识或权力合法性。
- 跨包游戏代码只通过 `@game-judge/game-engine/games/secrethitler/public` 导出。
- D1 注册迁移沿用生成器为 `game_type` 约束增加游戏类型，并在人工审查后加入游戏自有累计统计表；不创建单局历史表。
- 生产代码遵守仓库禁止普通类型断言、禁止 `console.*`、Worker 内部数据使用 `z.strictObject` 等约束。

## 11. 测试与验收计划

### 11.1 引擎测试

- 5–10 人的身份数量、阵营总人数和身份认知矩阵；所有人数配置均精确匹配表格。
- 首夜互认信息对 5–6 人法西斯阵营和 7–10 人普通法西斯正确可见；7–10 人希特勒、自由派和其他未授权视图不泄漏普通法西斯座位。
- 首任总统及身份洗牌使用可控随机输入，可重复验证，不依赖 `Math.random`。
- 身份查看门槛、首夜按 5–6 / 7–10 人选择正确语音、播报与私密查看两种到达顺序下的自动推进、非法提前进入选举、非本角色命令、座位冻结和重连恢复。
- 总理任期限制：通常 2 人限制、存活人数不超过 5 人时的例外、否决政府不更新限制、特别选举后恢复正常顺序。
- 投票秘密性、改票覆盖、全员提交前不揭示、全员提交后逐票揭示、平票否决。
- 连续 3 次否决、政策顶牌自动施行、忽略权力、任期限制和计数器重置。
- 牌堆不足 3 张时重洗、总统三选一、总理二选一、弃牌和施政记录不泄漏手牌。
- 否决权的解锁时点、总统接受/拒绝、否决计入失败计数及触发第三次否决。
- 5–6 / 7–8 / 9–10 人的每个轨道权力；政策预览不改变牌序；调查不能重复目标；特别选举的轮转复位；处决不泄露非希特勒身份。
- 5 张自由派政策、6 张法西斯政策、希特勒当选总理及处决希特勒四种终局边界。

### 11.2 Worker、Web 与契约测试

- Worker 严格拒绝缺字段、额外字段、错误阶段和越权命令；状态迁移仅接受受支持的版本。
- D1 注册迁移保留既有数据、约束、索引和级联关系；统计重复投递、回滚与重放不重复发奖或累计。
- 每种玩家身份在身份查看、首夜、立法、调查、政策预览、处决与终局复盘阶段只看到被允许的信息；首夜语音不出现姓名或座位身份泄漏。
- 房间 UI 覆盖配置校验、开局门槛、权限禁用、命令失败、离线重连、暂无数据、统计加载/错误及终局复盘。
- 注册表、引擎/Worker/Web catalog、静态客户端工厂、统计接线和能力声明均通过既有 contracts。

### 11.3 E2E

- 使用真实多浏览器上下文和真人座位，不用自动玩家填充 CI 座位。
- 覆盖至少 5 人、8 人和 10 人的身份知识差异、投票提交隐私、公投逐人亮票、暗投票数投影、政府立法和一条终局路径；所有 5–10 人轨道差异另由引擎合同测试覆盖。
- 用可控测试夹具快速走到调查、特别选举、政策预览、处决和否决路径；不得依赖偶然抽牌。
- 单 spec 经 actions API 验证后再加入 CI 分片清单；不得仅因生成器创建 `.tmpl` 就宣称 E2E 已上线。

## 13. 方案取舍与实施约束

### 采用标准规则，仅配置投票公开度

采用官方人数配置、三次连续否决、政策轨道权力和否决权；公投 / 暗投只改变结算后的选票公开度，不改变政府是否通过、政策效果或胜负。其余“平衡局”或规则变体必须作为独立产品决策和版本化规则评审。

### 采用累计阵营胜场而非单局排行榜

首版只保留累计完成局数与阵营胜场，既能表达核心玩法结果，也不引入逐局事件历史、胜率排名或回填问题。

### 商标、版权与美术

此方案仅描述玩法规则，不复用规则书原文、原版插图、卡牌图案、版式或其他美术资产。上线前须确认“Secret Hitler / 秘密希特勒”名称、主题呈现与素材使用的授权；未获确认前，不能把此设计文档视为商用许可。

### 已确认的产品决策与上线门槛

1. 按标准 5–10 人规则实现，默认 8 人，作为 `main` 层级游戏；首夜语音互认与 App 私密座位提示按 §5 执行。
2. 奖励采用 flat：33 XP、3 次普通抽奖、每日完成目标 1；赢家不额外加成。
3. 账户战绩累计完成局数、自由派胜场和法西斯胜场；胜率由相应阵营胜场 / 完成局数计算，被处决玩家仍按开局阵营记胜。
4. 开启 `identityViewing`、`audioOrchestration`；不启用 `stageDeadline`、`botBulkViewing`、词库或 E2E CI 激活。
5. 用户最新要求将游戏加入创建列表，因此设置 `isProduction: true` 并同步目录契约；这替代此前首个 PR 保持非生产的入口决定，不代表已部署生产。
