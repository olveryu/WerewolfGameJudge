# 一眼成对：新游戏设计与实施契约

状态：已批准开发，实施与验证记录见根目录 `new-game-spotmatch-report.md`。

游戏 ID：`spotmatch`；名称：一眼成对；副标题：同时找相同，抢先出完手牌。

最后更新：2026-11-17。

本定稿保留原设计的玩法、数学、网络公平、隐私和产品闭环要求；用户最后明确的决定覆盖早期草稿：
**2–20 人、默认 4 人；每人默认 8 张，可选 5 / 8 / 10 / 15；比赛没有时间限制，首位出完立即获胜。**
此前的 120 秒、按人数推导限时、超时获胜、多轮赛及生成器 preset 建议均已撤销，不作为实现需求。
原始完整草稿在开发会话中另存备份，批准的 200 个手绘 SVG 保留在游戏运行资源中。

## 2. 方向与边界

独立新游戏，不改故事接龙、你画我猜或其他游戏规则。首版仅出牌模式，不同时开发收集中央牌、淘汰赛、
技能、连击倍率、全球排位或自动竞技机器人。各玩家使用自己的手机，中央牌相同，个人顶牌不同。
一人出牌改变全桌正在寻找的匹配；其他人的顶牌与布局保持原样。

借鉴观察力桌游的数学机制，使用独立名称与用户批准的原创美术，不复制原版商标、卡面或说明书。
定位休闲线下聚会，不作反外挂赛事或“最快反应速度”的承诺。

## 3. 大厅、开局与有限牌量

大厅复用平台建房、加入、座位、资料卡、分享、配置及房主管理。要求配置的全部席位坐满才可开局。
2–20 指实际参与席位，不把未入座房主算作玩家；新进入者在比赛中旁观，下一局才能入场。
配置只在大厅修改，不允许进行中改人数、牌数或替真人判对。

开局冻结参与名单与机器人标记，随机选择中央牌与各人的当前顶牌；所有这些牌型互异。
每人初始剩余 `H` 包含已显示的顶牌，整局任务量 `N × H`，另有初始中央牌。
“未翻开的牌”是有限剩余任务数，**不是开局已排好的隐藏完整牌序**，动态补牌已获用户确认。

不实现早期草稿建议的 3 秒开局倒计时：该建议未独立获批，且为它引入 deadline 能力没有必要。
房主开始命令一次原子提交进入 playing，并同时披露中央牌与各玩家自己的顶牌，不存在另一个客户端发牌请求。

## 4. 数学牌组与动态补牌

使用 7 阶有限射影平面 `PG(2,7)`：

- 49 个仿射点 `(x,y)`，7 个斜率无穷远点、1 个垂直无穷远点，共 57 个点。
- 49 条 `y=mx+b mod 7` 直线、7 条垂直线与1条无穷远线，共 57 个牌型。
- 每牌 8 个不同点；所有不同牌型的 1,596 对组合恰有一个共同点。
- 每局从 200 个美术 ID 选择 57 个互异 ID，与数学点一一映射；同 ID 始终保持相同形状和配色。

正确出牌后，旧个人顶牌成为中央牌，个人剩余减 1。若剩余大于 0，从排除新中央与其他全部玩家顶牌的
候选牌型中选择下一张；其他玩家顶牌和布局完全不变。最多 20 人只占 21 种当前牌型，57 种池始终有余量，
不需要无界拒绝抽样或随机失败兜底。允许历史牌型重现，但每次出现使用新实例 ID。
“任意两牌唯一共同项”只承诺同时可见的不同牌型，不错误承诺所有历史实例两两如此。

### 不采用固定大牌组的数学原因

每张 8 图案、不同牌两两唯一匹配且无全局万能图案时，至多 57 个牌型：每个图案至多出现于 8 张牌，
固定一张牌的 8 个图案各至多连接另外 7 张，故上限 `1 + 8×7 = 57`。
单纯增加素材数不能让固定牌组同时支持20人每人8张。

可构造的固定档位为8图案/57牌、10图案/91牌、12图案/133牌、14图案/183牌。
9阶需真正的有限域，不能使用模9整数代替。上述更密档位未被选择，不在手机上偷偷改为14图案。

## 5. 手机舞台与美术

大厅采用共享 `seats`，比赛采用共享 `stage`，终局采用 `workspace` 与标准底部操作。
HUD 本人剩牌数、共享名单入口与代控操作嵌入舞台顶部，不再占独立栏；剩牌/提示/名单同一行，额外代控可换行，不横向溢出。
外框统一使用 `RoomStagePanel`，与 `RoomStageHud` 共同服务一眼成对、你画我猜、你画我猜接龙、轮流讲故事，不复制游戏私有边框、阴影与间距。
不增加“测试局”标签，不塞19个对手头像，不显示不存在的比赛倒计时；代控仅房主可见。
主舞台自上而下是固定高度的单一 polite 状态区、“桌面公共牌”标题与横牌、“你的手牌”标题与横牌。
标题紧邻各自牌面；两牌之间不再混放状态文案。网络状态只使用共享连接条，断线禁用两牌。
视觉采用已批准的 C 方案的粗描边、错位立体层次与弹跳确认，配合 B 方案的飞牌落桌、盖章动作；
保留应用现有蓝灰主题和语义成功/错误色，不引入紫黄配色、英文口号或另一套生产字体。
飞行牌只使用已经公开的新中央牌：本人成功由下向上，别人成功从侧面入场，不泄露他人手牌。
飞牌依据服务端暂停截止时间续播；减少动态效果时只保留静态确认，换牌/解锁不等待动画事件。
飞牌落桌后保持不透明直到静态新公共牌接替，避免淡出时露出旧公共牌；分段缓动不压缩三秒暂停时间线。

| 阶段 | 房主管理                                                     |
| ---- | ------------------------------------------------------------ |
| 大厅 | 共享任务卡/面板：配置、开始、分享、允许时清座/填机器人       |
| 比赛 | 共享标题栏管理入口，无底部房主任务卡；确认中止，不允许改配置 |
| 终局 | 共享复盘/再来一局/返回大厅任务和面板                         |

房主与是否入座是独立维度。机器人代控经共享名单抽屉和既有 takeover banner，
只控制机器人，不允许代打真人。最多20人的 roster 使用共享座位数据源。

### 5.1 素材与静态加载

`packages/web/src/games/spotmatch/assets/` 保存200个用户批准SVG和catalog，静态 Vite URL 导入；
生产代码不依赖评审原型，不通过 fetch 请求清单。全部200个素材可被选中，缺失是构建/测试错误。
不用 emoji 或系统字体图案作为卡牌替代。

### 5.2 稳定排布与触摸

牌面为 7:4 圆角横向长方形、最大宽度420 CSS像素；八个图案依据种子生成受约束的随机坐标，不套固定模板或排成直行。
任意高度为牌面内部高度22%的水平带中最多三个图案，避免出现明显的四图案横排。
每牌持久化 `layoutSeed` 控制坐标、图案大小和角度；同实例广播/重连/飞牌落桌均不重排，键盘顺序按视觉位置排列。
每个命中区至少52×52 CSS像素；1000组布局验证不同手机与最大牌宽下目标不重叠、在牌内，旋转缩放后的图案仍在目标内。

320×568、375×667、390×844 浏览器验收完整牌面、8个目标、最小44像素、无重叠和矩形边界。
桌面限宽；长昵称走共享名单而不挤牌。没有必须完成才能继续点击的飞牌/翻牌动画，
因此减少动态效果偏好下同样不播放游戏动画。按钮有图案中文名称、键盘焦点，不在 DOM/ARIA 标注正确答案。
无障碍名称不等于纯视觉竞速对所有视觉障碍玩家具有同等可玩性。

### 5.3 反馈与连接

公共牌与本人手牌上的图案均可提交同一 claim；两牌共用单飞锁，观战者不可点击。
正确出牌原子提交新牌与公开 success 元数据，服务端以 `success.until = nowMs + 3000` 拒绝全桌新操作。
暂停内所有人看旧公共牌上的绿色匹配框与出牌者姓名；飞出的旧手牌单独渲染，出牌者下方立即补上权威新手牌，其他人手牌不变。
三秒暂停仅阻止操作，不延迟补牌，也不给新手牌标上上一张牌的绿色匹配框。
截止后新公共牌接替飞牌；最后一张下方立即显示“手牌已出完”，保留飞牌起点的占位尺寸，成功反馈后再显示终局，不重复结算。
合法误点只锁本人 `lockedUntil = nowMs + 1000`，权威 `lastMistake` 绑定双实例与符号，点中的符号显示红框，并明确提示锁定一秒。
客户端收到服务端误点确认就立即锁住双牌一秒并显示红框，不等待快照；本地确认绑定当前局和操作座位，不影响其他座位。
本地计时只负责显示与恢复按钮，延迟回执和重连使用剩余绝对时间，不能从收到快照起重新等一秒。
旧牌只内联提示“被抢先了，再找一次”，不罚、不弹窗，仍记录日志；真正网络/权限/异常保留平台错误反馈。
所有普通交互反馈在 HUD 中间的单一 polite 状态区，与剩余张数和名单同一行；无动画也必须可读，不重复共享网络提示。

### 5.4 结束页

终局以共享 `RoomStagePanel` 展示奖杯与赢家，复用从你画我猜抽出的 `RoomRanking` 展示引擎权威名次、自己标记、剩牌、出对与误点。
名次不由 UI 重算；含机器人时保留不计战绩与奖励的提示。复盘、再来一局、返回大厅仍只有共享房间外壳提供的入口。

## 6. 命令与网络公平

`spotmatch.card.claim` 输入：

```text
roundId
centralInstanceId        # 用户看到的中央牌实例，不是牌型
topInstanceId            # 用户自己的当前顶牌实例
symbolId
```

使用已有 HTTP `POST /room/command`、标准 `commandId`、acting-seat、receipt、snapshot revision 与 RoomLink；
不增加第二种 transport。Durable Object 串行提交，校验顺序：

1. 用户/座位权限；controlledSeat 必须是房主代控机器人。
2. 仍处于 playing。
3. roundId、中央实例、本人实例与剩余手牌有效。
4. 本人误点锁定和全桌成功暂停均已结束。
5. symbolId 属于当前中央牌与本人顶牌的并集；并集以外拒绝为非法输入。
6. 若仅在其中一牌：**提交事件和 `domainRejected` outcome**，误点+1、锁本人至 `nowMs+1000`，不锁其他人。
7. 若同时属于两牌：一次提交中央变更、个人剩余/正确次数、新顶牌、公开成功元数据与3000ms暂停截止；首空同次进入终局。

过期检查在误点解释之前。两个并行请求中先提交者改变中央，后者旧中央明确 stale，
即使图案也匹配新中央也不重解释。不能以房间revision代替牌实例，昵称等无关更新不影响出牌。
重复commandId返回原回执，不再次计错/减牌/结算；冷却中尝试不计错、不延长锁定。
图案不在两张当前牌的并集中是非法输入，不作为一次正常猜错。

以服务端接受并提交顺序为准，不信任客户端点击时间，不做回溯、事后改判或复杂延迟补偿。
正确出牌有用户明确选择的全桌共享3秒反馈暂停，与误点仅锁本人相互独立；
使用服务端时间戳守卫，不为每次出牌增加内部定时命令。动态补牌无外部AI或第二次网络往返。
网络延迟影响公平，不宣称完全消除，也不发布反应速度排行榜。

## 7. 完整状态机与时限

```text
lobby
  └─ 房主合法开始，全部席位坐满 → playing（立即亮牌、无比赛时限）
       ├─ 正确出牌后仍有剩余 → playing（原子动态补牌，全桌反馈暂停3000ms）
       ├─ 合法误点 → playing（仅该玩家锁定1000ms）
       ├─ 首人剩余变0 → ended（唯一赢家，自动发一次结算effect）
       └─ 房主确认中止 → lobby（保留座位/配置，清空本局，不发完成effect）
ended
  ├─ 再来一局 → playing（新局号、新牌实例、清空次数/锁定）
  └─ 返回大厅 → lobby（保留座位/配置）
```

无 opening deadline、比赛 deadline、客户端 expire 命令、超时胜负或隐藏自动收局。
误点锁定不是阶段截止，不启用 `stageDeadline`。平台房间到期回收不是游戏自然完成。
奖励用既有自动结算链路，不增加“手动发奖/完成”按钮。

## 8. 胜负、排名与得分

唯一胜者是首位成功将自己的剩余变为0的参与者，包含匿名玩家与机器人；
不能先筛奖励资格再把胜者转让给其他注册玩家。其余按剩余从少到多排名，
并列采用竞赛排名（如1、2、2、4），并列排名不等于并列胜利。
不另设“正确+1”“抢先加分”或反应速度积分。正确次数用于复盘和累计统计。

## 9. 配置与共享机制

| 字段            | 默认 | 合法值       |
| --------------- | ---- | ------------ |
| numberOfPlayers | 4    | 2–20 整数    |
| cardsPerPlayer  | 8    | 5、8、10、15 |

引擎 `SPOTMATCH_CONFIG_SCHEMA` 是唯一配置声明；Worker通过configSchemaToZod，
web通过标准GameConfigForm消费。共享 choice 字段支持数字选项，不误显示为“秒”，不另造配置页。
无图案数滑块、时长输入、机器人难度、多个卡包。

当前生成器没有preset。可选能力全部关闭；基础 `botsAndTakeover`、`hostConfig` 保留。
身份查看、翻身份动画、音频、词库、gallery 均不需要。共享外壳使用stage不等于生成器需要某个preset。

## 10. 隐私、旁观和断线

| 信息                                    | 本人                                 | 其他真人/旁观者 |
| --------------------------------------- | ------------------------------------ | --------------- |
| 中央牌、各人剩牌数、正确/误点、公开结果 | 可见                                 | 可见            |
| 本人当前顶牌                            | 可见                                 | 不可见          |
| 其他真人顶牌                            | 不可见                               | 不可见          |
| 未来牌序/随机种子                       | 不存在预排牌序；命令随机源不传客户端 | 不可见          |

host不因管理权限获得真人顶牌；只有bot顶牌可供host使用共享代控。
服务端模块 `projectStateForUser` 在 HTTP新回执与重放、WS SYNC、STATE_UPDATE 序列化前裁剪，
不是前端CSS隐藏。权威持久化/回执存储仍保留完整状态，投影不修改权威数据。
公开57素材映射不暴露任何真人的隐藏当前牌型，也不包含未来随机状态。

断线/离开页面不等于放弃，不自动替玩家出牌；回来时按最新中央继续。
首版沿用共享进行中座位冻结，不新增独立“放弃/DNF”命令；这是早期草稿建议的收敛，
避免没有共享生命周期支持时凭空发明人数不足自动终局。若以后加入明确退赛，必须先定义DNF与结算排除。
长时间无人在线按房间生命周期回收，不补造完成记录。

## 11. 机器人与试玩

占座与手动代控沿用平台；任何自动mock对手只属于原评审mock，不进入生产。
冻结开局存在任何bot则整局test，不因后来操作而转为正式局。
不让系统自动识别共同项并延迟出牌。E2E使用多个独立真人浏览器context，不用bot填席。

| room.seat.*                  | 共享身份/座位命令；大厅             | 更新共享roster                 | 共享占座/权限/阶段原因                |
| spotmatch.config.update      | 房主，大厅，合法config              | 更新配置                       | 配置无效/占用越界/非房主              |
| spotmatch.game.begin         | 房主，大厅或终局，满座              | 新局号、原子亮牌               | 未坐满/非房主/阶段错误                |
| spotmatch.card.claim         | 本人或host代控bot，当前局/实例/图案 | 正确原子出牌；误点提交领域结果 | stale不罚、非法图案不计错、冷却不重计 |
| spotmatch.game.abort         | 房主，playing，确认                 | 回大厅、不统计不奖励           | 非房主/阶段错误                       |
| spotmatch.game.returnToLobby | 房主，ended                         | 清空本局、保留座位/配置        | 非房主/阶段错误                       |
| 重试命令                     | 标准commandId/receipt               | 原始结果                       | 标准冲突/网络恢复                     |

合法误点反馈“没有匹配，1秒后再试”；冷却反馈“稍等一下再试”；
非法图案“操作无效，请同步后重试”；终局后拒绝新出牌。
不提供到期推进、角色查看、替真人出牌或自定义发奖命令。

## 13. 奖励与业务统计

### 13.1 资格与归属

- 结算单位是一整局，不是每张牌或每次刷新。
- 只有自然首空终局；开局冻结真人至少2人，匿名真人计门槛，bot不计。
- 任一bot使全局不发业务统计和奖励。
- 实际接收者是本人至少正确出1张的注册真人。引擎按冻结座位顺序生成事实，
  Worker既有注册/匿名门保证匿名玩家无持久奖励/统计。
- 中止、回收、无人出牌不补造完成；不把匿名赢家排除后重新发胜利。
- 奖励固定5 XP、1普通抽奖，日目标5局；赢家无额外经济奖励。

### 13.2 指标

| 指标         | 权威事实                                | 单位/展示         |
| ------------ | --------------------------------------- | ----------------- |
| gamesPlayed  | 每个符合资格的终局1                     | 局                |
| wins         | seat === winnerSeat                     | 局，只有首空者为1 |
| correctCards | 本局成功出牌数                          | 张                |
| mistakes     | 本局合法误点数，不含stale/冷却/非法输入 | 次                |
| 胜率         | wins / gamesPlayed                      | 百分比，零分母“—” |

公开DTO、严格v2 completion facts、game-owned D1 `spotmatch_user_stats`、
Worker getter/settlement、设置页catalog统计与房间资料卡复用同一数据链。
不做完整行动数据库、反应速度/平均毫秒或历史回填。

### 13.3 原子性、兼容与缓存

事实在terminal事件演化后取值；效果只发一次。既有outbox+settlement `stats_applied` 边界
原子应用奖励与所有计数；重试不重复。严格v2缺字段/错顺序/重复用户拒绝，不能降级legacy。
legacy reward-only形态保持只奖励，不虚构统计。新状态版本1，未知/更高版本拒绝。
completedAt为服务端Unix整数毫秒；不生成没有定义的耗时指标。
统计effect异步落库，账号收件箱既有query-key失效刷新；pending/error不冒充零，也不伪造本地加一。

## 14. 标准终局复盘

游戏只生成封闭词汇的 `RoomReviewDocument`：赢家hero、按剩牌排序的全员roster，不增加“测试局”标签，
列明名次/剩牌/正确/误点。所有观看者可打开并分享，使用平台唯一复盘弹窗、捕获、导出与分享流程。
不增加游戏专用review modal，不披露未出真人顶牌，不输出commandId或鉴权信息。

## 15. 状态、不变量与随机性

state包含phase、phaseRevision、config、roster、gameSequence、xpSettled和nullable round。
round包含roundId、central、symbolMap、players、serial、isTest、winnerSeat、lastPlayedSeat、success。
success公开seat、symbolId、previousCentral、until；只含已公开或已打出的牌，不披露未出的真人手牌。
player冻结seat/userId/isBot，记录remaining/correct/mistakes/lockedUntil/lastMistake/top；
lastMistake只投影给本人或房主代控的bot，不向其他人披露私人手牌符号。
状态版本2显式迁移已存在的版本1房间：保留原牌/分数/锁定，新增success与lastMistake置null，不伪造历史反馈。
card有typeId、唯一instanceId、layoutSeed、8个symbolId。

随机性只使用既有 `context.randomSeed` 与 `createSeededRng`；引擎不访问Math.random、crypto、clock或网络。
时间只用注入的nowMs。每次命令有独立随机源，不持久化或公开未来随机序列。

不变量：单牌8不同符号；当前central与所有活动top类型互异；实例ID互异；
每人remaining+correct=H；winner只在终局且剩余0；isTest由冻结bot决定；
当前top不是未来可猜牌，终局不能被迟到命令改写。投影里的他人top为null，权威状态不被投影修改。

## 16. 工程接入与迁移

生成命令实际只执行一次：

```sh
corepack pnpm new-game spotmatch --name 一眼成对 --subtitle '同时找相同，抢先出完手牌'
```

基础47文件、17共享注册编辑，报告另计。保留生成报告并逐项处理9步，不重复生成。
三个game slice遵循各包AGENTS和唯一public入口。RoomLink/HTTP协议不改；
仅给Worker module增加可选通用viewer投影seam，旧游戏默认行为不变。

`0089_spotmatch.sql`扩展注册CHECK并创建自有累计表：
重建rooms、room_game_starts、room_participants、fib_round_word_selections、
undercover_round_word_selections、product_game_reward_results，保留其数据/约束/外键与7个显式索引，无新增历史账本。
自有统计主键user_id、账号删除级联，四个非负整数，wins≤gamesPlayed。
一次性成本为上述六表各全量读取/写入一次并重建索引；上线前按生产行数和索引项估算，当前不声称知道生产规模。
累计查询主键查单用户，不加二级索引；settlement跟既有幂等批次，重试不额外计数。
测试验证8/256无关账号时读取≤2行，统计写入相较基线最多增加行和主键项2次。

## 17. 测试与验收

- 数学：全部1596对；20人140次动态出牌（超过57），当前类型互异、别人top不变、旧类型回归不能重放实例。
- 引擎：双牌共同符号/各自独有符号/并集外非法/误点1000ms与全桌暂停3000ms边界；先权限与实例后误点；首空/迟到/新局/中止/含bot/匿名赢家不转让。
- Worker：HTTP回执及重放、WS sync和broadcast私有裁剪；误点回执重试只计1；
  strict schema/DTO、legacy/v2、奖励与统计回滚/幂等/匿名门、迁移保留和查询成本。
- web：200素材与1000布局、共享guidance/review、统计pending/error/empty/count/胜率、
  真实stage的八目标、连接锁定、无乐观游戏状态。
- E2E：2个独立真人context，在320×568、375×667、390×844真实建房/配置/点牌/对方顶牌不变/终局/标准复盘/回大厅。
  spec只注册1个CI shard；未经用户允许不push或dispatch远程单spec。

20真实设备/连接竞争负载、微信web-view与至少两部真机同桌的误触/辨识和p50/p95测量仍属发布前人工验收，
不能用20人引擎数组测试或桌面模拟视口冒充已完成。没有测量前不作延迟阈值承诺。
本地只运行scoped tests、对应typecheck、root tsc、knip、changed lint/format；
完整quality/E2E门禁交给CI，详见接入报告的实际证据。

## 20. 确认记录

最终已确认：一眼成对/spotmatch；2–20默认4；每人默认8且5/8/10/15可选；
无比赛时限；57牌型动态循环与每实例唯一ID；200批准原画每局映射57；
两牌可点，误点仅锁本人1000ms且stale不罚，正确全桌共享暂停3000ms；标准共享stage/名单/host管理；
