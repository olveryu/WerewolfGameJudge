# Grill: 抽身份道具

Date: 2026-11-26

## Intent

在线下游戏中使用通用道具：房主配置身份牌，玩家自行抽取自己的身份。

## Constraints

- 同一房间可启用多个道具；房主在创建房间的配置页选择，本局开始后锁定，参与玩家在开始时确定。
- 开始前，房主可在主持管理中通过「房间设置」修改本局启用的道具。
- 创建房间时至少选择一个道具，默认选中骰子；全部取消时提示先选择道具。
- 房间不显示座位表、不设置固定人数上限；使用行动手牌入座，房主也自主选择是否参与。
- 显示入座人数及当前房间总人数，后者包括参与者和观众。
- 断线人员仍计入房间总人数，直到主动离开；总人数不是实时在线人数。
- 线下玩家互相认识，不需要为同一账号同时在多个设备进入同一房间增加限制；换设备后重新进入仍可恢复本局状态。
- 开始前可取消入座，至少一人入座才能开始；开始时锁定参与身份，离开或重进不自动改变身份。
- 房主可在准备阶段让全部入座者站起来，按其他游戏的清空座位交互确认后执行；不让玩家离开房间。
- 同一账号不能重复入座；断线不取消入座或参与资格，恢复连接后可继续使用本局道具。
- 开始后进入房间的玩家是观众，只能观看公开信息，不能使用道具。
- 开始后明确显示本人的身份：参与者显示「本次参与中」，观众显示「观看中」。
- 手牌体现自己的入座状态。
- 玩法规则由线下玩家决定，不提供骰子亮骰功能。
- 道具箱采用工具模式：房主主动结束本次使用，不发游戏奖励、不计游戏局数。
- ~~结束后返回准备状态，重新选择道具和入座，清空本次骰子及身份结果。~~ 已被 2026-11-26 决定取代：重新开始保留入座和配置，只清空本次骰子及身份结果。

## Key decisions

- 内部游戏 ID 使用 `toolbox`，展示名为「聚会工具」；介绍中说明骰子、卡牌等道具。
- 不提供机器人，供真人使用；需要适配现有平台契约。
- 第一版卡牌为自定义身份牌，普通扑克牌以后再加；介绍写明骰子和身份牌。
- 每人可选 1–20 颗骰子，默认 5 颗；固定的骰子计入总数。
- 修改骰子数量在下次摇骰时生效；此前已掀开的骰子保持原样。
- 减少数量时从右往左移除未固定的骰子。
- 如果目标骰子数量小于已固定数量，先手动取消固定足够的骰子，再减少数量；不自动移除或解锁固定骰子。
- 骰子操作导致数量与固定状态冲突时弹窗说明，让用户自行修改，原状态不变；不会自动调整目标数量。
- 骰子结果和固定状态由房间保存，仅本人可见；刷新、重连或换设备后可恢复。
- 身份名称、可选说明和各身份数量由房主自定义，不提供预设身份。
- 同一套配置中身份名称不能重复；相同身份用数量表示。判断重名时与方案名一致，忽略首尾空格、区分英文大小写。
- 房主设定每人可抽牌数；玩家逐张抽取一副共享牌堆，抽走不放回。
- 牌数不足时不能开始；多余牌保留在牌堆。
- 身份仅抽牌者可查看，关闭弹窗后仍可再次查看。
- 身份种类、数量与说明公开；这可能使玩家根据配置推断他人身份，但不能直接看到他人的抽牌结果。
- ~~房主可重开身份轮次并修改配置，只重置身份牌，不影响其他道具。~~ 已被 2026-11-26 决定取代：不提供「重开身份牌」。
- ~~配置页选择道具，房间展示已选道具；开始时按需配置身份，然后确认开始。~~ 已被 2026-11-26 最终确认取代：身份牌在设置页配置。
- 2026-11-26：信息卡沿用共享模式：设置项「本次工具」「每人抽」，启用身份牌时用 BoardInfoContent 列身份小标签（名称×数量），点击用共享 RoleCardDialog 显示名称、数量和说明；不另做「看配置」按钮。准备阶段展开、使用中折叠并可从「配置」入口查看。Reason: 与狼人杀、谁是卧底、阿瓦隆一致，无需新组件。Alternative rejected: 「查看身份配置」按钮；只列设置项。
- 2026-11-26：身份配置不放在中央状态区；公开配置放在共享房间信息卡（RoomGameSummary），与其他游戏一致。Reason: 信息卡本来就承载本局设置。Alternative rejected: 中央状态区显示身份摘要。
- 2026-11-26：准备阶段中央状态区只显示现有入座状态文案（已入座「等待房主开始」），不显示身份配置，也不广播「房主正在配置」类状态。
- 2026-11-26 最终确认（推翻同日「开始时配置」方案 A）：身份牌在设置页配置——建房配置页与准备阶段「房间设置」都使用 mock 的身份编辑器；房间内「开始游戏」为正常共享开始流程，牌不够时开始按钮禁用并说明原因。Reason: 设置页更方便，开始流程保持与其他游戏一致。Alternative rejected: 开始时弹窗配置身份牌。
- 2026-11-26：勾选身份牌后，建房设置页和「房间设置」都必须配好至少一种合法身份才能保存（前端校验与引擎 `toolbox.config.update` 一致），因此不存在「已启用身份牌但未配置」的房间状态。
- 2026-11-26：准备阶段牌数不够每人抽时，只有房主在「开始游戏」的禁用原因里看到「身份牌不够每人抽，请在房间设置中调整」；其他玩家只看到「等待房主开始」，不广播。Reason: 只有房主能处理；与其他游戏一致。Alternative rejected: 中央状态区对所有人提示。
- 2026-11-26：删除「重开身份牌」。要换身份，房主只能「重新开始」回到准备，在「房间设置」改配置后再开始。Reason: 避免使用中出现旧身份作废、抽牌与重开竞争的中间状态。Alternative rejected: 保留重开并在抽牌弹窗提示旧身份作废。
- 2026-11-26：设置页勾选身份牌后只显示「身份配置」入口卡（摘要身份、张数与已入座所需张数），点击打开「配置抽身份」弹窗编辑；「完成」校验后回到设置页，取消丢弃弹窗内修改；未配置时设置页提示「请先配置身份牌」并禁用提交。Reason: 与已确认 mock 的弹窗一致，避免编辑器平铺撑长设置页。Alternative rejected: 页面内平铺编辑器；可展开卡片内编辑。
- 2026-11-26：「重新开始」保留入座和配置（含已选工具），只清空本次骰子和身份结果；已离开房间的参与者不保留入座。Reason: 改完设置即可直接开始，不必所有人重新入座；与其他游戏重新开始保留座位一致。Alternative rejected: 清空入座、重新选择工具。
- 可按账号保存多套命名身份配置供跨设备复用；道具选择不包含在内。复用后修改仅影响本局，需主动更新原配置或另存新配置。
- 同一账号不能保存同名身份方案；遇到同名时提示用户修改名称。
- 判断方案是否同名时区分英文大小写，忽略名称首尾空格。
- 微信账号与已有邮箱账号合并时，若两边有同名方案，两套都保留；微信侧方案自动加「（微信）」改名，仍冲突则加数字。
- 匿名用户不能保存身份方案；微信登录是正式账号，无需绑定邮箱即可保存，邮箱正式账号同样适用。
