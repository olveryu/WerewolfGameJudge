# Grill: 可复用的新游戏 UI Mock

Date: 2026-11-26

## Intent

减少 AI 制作新游戏 UI mock 的时间，并避免遗漏现有公共组件。

## Constraints

- 游戏实现之前和之后都要能预览；使用离线假数据，真实联机另行验证。
- 能切换阶段和角色、打开弹窗并展示关键状态，不要求从头玩完整游戏。
- 第一阶段覆盖游戏首页、配置页和房间等完整页面。

## Key decisions

- 默认沿用真实公共组件的现有样式和行为，偶尔比较新样式。
- 使用项目内统一的本地预览入口，而不是每次生成独立 HTML。
- 用公共页面和状态清单检查遗漏；交付时列出不适用项及原因。
- 新游戏专属 UI 尽量做成正式版可复用的组件。
- 首先用秘密希特勒做样板，对照真实页面验证预览。
- 新游戏 mock 默认复用预览入口和清单；特殊情况可以说明原因后例外。
- 下一步先检查代码并提出具体方案，不实现。
- 用户确认 mock 后，正式实现直接提升 mock 组件和交互结构，不重写；偏离先获确认。原因：聚会工具正式实现重写 mock 后出现身份牌、手牌和按钮名称全部不一致。
- 房主操作和公共信息复用共享 builder 与共享名称（清空座位、重新开始、开始游戏），不自制按钮或改名。
- 实现后预览渲染真实页面，场景由真实引擎命令生成，mock 副本删除。

## Open questions

- 首页、配置页及房间的真实组件能否离线复用，以及需要怎样的改造。
- 如何隔离公共组件的新样式探索。
